# MoUI 0.5.0 — Platform Bridges

自 `0.4.0` 以来的功能版本。25 个公开模块统一到 `0.5.0`（延续 ADR 0065 的
synchronized-line 政策）。本线核心：**Android 与 iOS 两条 window-hosted
路线全部晋升 `committed`**、**移动端剪贴板 / 无障碍 / 命名键三条宿主桥
落地**、**shell 内容宽度修复**、以及 addon 模板与 workspace 工程卫生收口。

本版不引入应用面 API 破坏——只新增公开符号（剪贴板与无障碍桥、命名键
事件通道），标准应用面（`@moui` + 领域 facade + `moui/views`）无需改代码。
按兼容性策略，需要新公开符号的变更进入 minor 而非 patch。

## 平台等级（ADR 0066 / 0067）

| 平台 | 等级 | presenter | 证据 |
|---|---|---|---|
| Android | **committed** | `cpu-blit-anative-window` | emulator-5554 上 R6 全能力观察 |
| iOS | **committed** | `cpu-blit-calayer` | iPhone 17 模拟器上 R6 全能力观察 |
| HarmonyOS | committed | `egl-direct` | （ADR 0046，维持） |

R6 七项能力（pixels changed / input received / detach / IME / clipboard /
accessibility / async image）在两条移动路线的匹配模拟器上全部观察记录于
`checks/platforms/{android,ios}.json`。iOS 的设备旋转未捕获 live 观察——
自动化宿主的 TCC 权限阻断了全部旋转机制，作为证据限制记录在 manifest 中
（rotation 不在 R6 能力列表内）。metal-direct / vulkan-direct GPU 直呈
七门槛声明仍是独立渲染器条目。

## 平台桥（新增公开符号）

- **剪贴板**：Android 走 window embedder 的 JNI ClipboardManager 桥
  （`mbw_android_clipboard_write_text` / `_read_text`），iOS 走通用
  UIPasteboard（`mbw_ios_clipboard_write_text` / `_read_text`），
  HarmonyOS 的 OH_Pasteboard 契约不变。三条路线统一由
  `app_environment()` 的 `ClipboardServices` 与
  `HostedWindowBackend::service_handler` 同步应答。
- **无障碍**：Android 的 `AccessibilityNodeProvider` 桥与 iOS 的
  `UIAccessibilityElement` 桥把运行时语义快照发布给平台无障碍栈
  （`android_accessibility.mbt` / `ios_accessibility.mbt`，同一平面编码）。
  激活动作回流为节点中心合成 tap（TalkBack/VoiceOver 的双击激活契约）。
  关键实现约束：Android provider 的 HOST 分支必须调用
  `host.onInitializeAccessibilityNodeInfo(info)`，否则整棵虚拟子树对
  TalkBack/uiautomator 不可见。
- **命名键**：Android `MBW_ANDROID_HOST_KEYBOARD_KEY` 13、iOS
  `MBW_IOS_HOST_NAMED_KEY` 16——硬件 Return/Backspace/Tab/Escape/方向键
  到达运行时 `KeyboardInput`；iOS 的 Return 经代理 `insertText:@"\n"`
  拦截以保证提交而非编辑。

## 修复

- **Showcase shell 宽度**：平台 `view_body` 忽略 shell 量的内容宽度，导致
  页面列回退到固有宽度（约 292 逻辑像素）。修复后按 shell 宽度钉住
  `.frame(width=width)`（实测卡片 24..399 满内容宽）。
- **iOS 模板 plist**：补 `UIDeviceFamily`、`CFBundleInfoDictionaryVersion`
  与横屏方向声明——缺失时 SpringBoard 以 "not valid application" 拒装。
- **addon 脚手架命名**：文件与构造器名跟随 canonical addon-package-guide
  的 snake_case 约定（`<id>_control.mbt`、`<id>_badge`）。

## 工程卫生

- 全 workspace `moon check` 警告清零（966 任务全量重查）。
- 治理校验器的 product 意图识别 `committed_with_gaps` 档位；
  repo-docs 校验器的 presenter 词表区分 direct-present 与 CPU-present。
- `checks/source-file-policy.json` 预算登记按 pr 门槛暴露的存量
  （scroll_view 拆分、api-surface 校验器 1850→1900）。

## 升级说明

- 从 0.4.0 升级：无需应用代码改动。`wzzc-dev/window` 依赖继续
  `0.5.4-0.2.5`。
- 平台清单中 Android/iOS 升为 `committed`：Tier 3 依旧不阻塞发布；
  GPU 直呈七门槛与 live 旋转观察的跟进项见
  `docs/platform-readiness-declaration.md`。
