# MoUI 0.4.0 — Architecture Convergence

> Status: released 2026-11-06. The synchronized line is `0.4.x` (ADR 0065).

0.4.0 is a declared breaking architecture release on the normal `0.x` minor
path. It has no compatibility layer: moved symbols are removed from their old
package in the same release, and every in-tree call site plus the external
consumer fixture moves atomically.

## Breaking changes

### Host orchestration moves to `moui/apphost`

- `moui/runtime` no longer exports `HostRuntimeDriver`, `RedrawScheduler`,
  `AppBuilder`, `AppLaunchRequest`, `PlatformEntry`, `run_app`,
  `run_async_pump`, the host event subscription adapters, or the platform-view
  plugin install/sync helpers.
- Import `wzzc-dev/moui/apphost` and call `@apphost.run_app(...)`,
  `@apphost.HostRuntimeDriver`, and the other moved names.
- `moui/runtime` production imports only `moui/core`.

### Text paragraph caching leaves `moui/core`

- `TextSystem::layout_paragraph` becomes direct dispatch; the owner-local cache
  lives in `moui/render/common` and is installed by each renderer factory.
- Font registration invalidates only the owning renderer/session cache.

### Services gain an extension registry

- `AppServices::new` accepts `extensions~`; `AppServices::extension(id)` returns
  a typed-versioned `ServiceExtension?`.
- Built-in seven service groups keep their existing typed getters.

### Renderer resolution reports rejections and capability plans

- `resolve_renderer` is replaced by `resolve_renderer_with_plan`; the result
  carries the bound session, ordered rejection reasons, and a capability plan.
- `AppBuilder` gains startup preflight and feature requirements.

### Unified diagnostics

- A diagnostics subpackage under `moui/core` defines `DiagnosticEvent`,
  severity/domain, stable codes, and a caller-owned bounded sink.
- `RenderFrameResult` carries per-frame `DiagnosticEvent` values.

### Task lifecycle

- `TaskScope`/`CancelToken`/generation become the shared cancellation contract
  for `ServiceTask`, image requests, and the GPU worker.

### Multi-window AppShell

- `WindowProgram`/`AppShell` become the first-class multi-window composition
  model; `examples/mo_desktop`/`examples/multi_window` stop carrying their own
  window registry.

## Migration

1. Add `wzzc-dev/moui/apphost` to every composition-root `moon.pkg` and replace
   `@apphost.run_app` with `@apphost.run_app`.
2. Replace `@runtime.HostRuntimeDriver`, `@runtime.HostPlatformEventSources`,
   and `@runtime.RedrawScheduler` with their `@apphost` equivalents.
3. If you constructed `AppServices`, add `extensions~` only when you need a
   third-party service; the existing named arguments are unchanged.
4. If you called `resolve_renderer`, switch to `resolve_renderer_with_plan` and
   read `resolution.plan` for rejection reasons.
5. If you consumed `RenderFrameResult`, read `diagnostics` for per-frame
   degradation facts.
6. Re-run `moon info` for every package you publish.

## Release-window generator switch

`moui new` and MoUI Studio export bundles now pin `0.4.0` and generate
`moui/apphost` composition roots. The CLI defaults, Studio version table, and
both generated package templates moved in the same release window; this is a
generator pin, not a framework compatibility layer.

## Deferred to 0.5.0

- **First-class `AppShell`/`WindowProgram`** — ADR 0064 keeps the existing
  `WindowActions`/`WindowScene` pattern for 0.4.0 and moves the product API
  design gate to 0.5.0.
- **Image/GPU `TaskScope` adoption** — `ServiceTask` uses the new
  `TaskScope`/`CancelToken`; image requests and the GPU worker keep their
  existing tokens until the next slice.
- **Diagnostic producer migration** — Skia, Sun, and TUI report per-frame
  degradation through `RenderFrameResult.diagnostics`; image lifecycle,
  embedded wire, and Agent/DevTools consumption follow in 0.5.0.
- **`moui/core`/`moui/runtime` domain split** — the multi-signal trigger is
  2,735 mbti lines, 1,159 public declarations, and 146 importing manifests at
  this window; it does not fire, so the split is re-measured next release.

## Notes

- `HostWallClock` stays in `moui/runtime`; it is a pure value type.
- Semantics DTOs (`SemanticsRead`, `PerformSemanticsActionRequest`, receipts and
  errors) stay in `moui/runtime` and are re-exported by `moui/apphost` for the
  backend-common owners.
- The released line is synchronized: every public module moves to `0.4.0`
  together (ADR 0065). See `docs/compatibility-matrix.md`.
