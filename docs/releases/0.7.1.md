# MoUI 0.7.1 — Sun Linux font candidates

Patch release since `0.7.0`. All 26 public modules move to `0.7.1` together on
the existing `0.7.x` release line (ADR 0065; the line does not advance). A patch
on this line carries bug fixes and documentation only.

This release fixes one defect: on Linux the Sun renderer picked a different text
face than Skia, which put the blocking `Sun/Skia visual profile` gate over its
average budget in the CI font environment. No public API, package boundary, or
host wire contract changed.

## Sun Linux font candidates (PR #29)

- **Cause**: Skia's fontconfig provider walks an explicit candidate list
  (`skia_system_sans_families`, `skia_monospace_families`,
  `skia_serif_families` in `moui_skia_renderer/renderer_text_glyphs.mbt`) and
  keeps the first match whose family is the requested one. Sun asked fontconfig
  for the generic role (`sans-serif` / `monospace` / `serif`) instead. On a host
  with Noto installed fontconfig resolves `sans-serif` to Noto Sans, while Skia
  never looks at the generic alias and keeps picking the earlier DejaVu Sans
  candidate — same host, same app, a different face for every text control.
- **Fix**: Sun probes the same candidate names in the same order
  (`moui_sun_renderer/renderer_platform_font_query.c`) and accepts a face only
  when `fc-match` echoes the requested family back, so a weak alias (Arial on a
  host without Arial resolves to Nimbus Sans) is discarded the way Skia discards
  it. The generic role query stays as the fallback when no candidate resolves,
  so a host with a nonstandard font set still draws text.
- **Cost**: the probe resolves once per process alongside the weight buckets;
  face registration and the glyph cache are unchanged.
- **Gate evidence**: in the CI font environment the profile drops from
  `avg 3.36%` / `worst 8.50%` to `avg 1.19%` / `worst 2.61%` (limits `3.00%` /
  `10.00%`). The worst cells: `checkbox/dark/focused 8.50 → 2.55`,
  `checkbox/light/default 8.19 → 2.21`, `text_field/light/default 3.85 → 2.61`,
  `text_field/dark/default 3.93 → 2.58`. No threshold, gate, or candidate list
  was relaxed or reordered to get there.

## Upgrade notes

- Update dependencies; no public symbol was added or removed, and no package
  boundary or wire contract changed. The `wzzc-dev/window` pin is unchanged from
  `0.7.0`.
- On a Linux host whose generic `sans-serif` resolves to a family that is not
  first in the Skia candidate list — the common case on a Noto-based desktop —
  Sun now draws the same family Skia draws. Text metrics on those hosts change
  slightly; that is the fix, not a regression.
- Apps that bundle and register their own faces are unaffected: the candidate
  list only feeds the default platform font discovery.

# MoUI 0.7.1 —— Sun 的 Linux 字体候选表

自 `0.7.0` 以来的补丁版本。26 个公开模块统一到 `0.7.1`，仍然留在 `0.7.x`
发布线（ADR 0065，本版不推进线号）。本线上的补丁版本只做 bug 修复与文档。

本版只修一个缺陷：Linux 上 Sun 渲染器选到的文本 face 与 Skia 不同，导致
阻塞的 `Sun/Skia visual profile` 门禁在 CI 字体环境下超出平均值预算。没有
公开 API、包边界或宿主协议变更。

## Sun 的 Linux 字体候选表（PR #29）

- **成因**：Skia 的 fontconfig provider 走显式候选表（`skia_system_sans_families`、
  `skia_monospace_families`、`skia_serif_families`，见
  `moui_skia_renderer/renderer_text_glyphs.mbt`），只保留命中请求 family 的
  第一个匹配。Sun 问的是 fontconfig 的通用角色（`sans-serif` /
  `monospace` / `serif`）。装了 Noto 的宿主上 fontconfig 会把 `sans-serif`
  解析成 Noto Sans，而 Skia 从不看通用别名、继续拿更靠前的 DejaVu Sans
  候选 —— 同一台机器、同一个 app，每个文本控件都是另一种 face。
- **修法**：Sun 按同样顺序探测同样候选名
  （`moui_sun_renderer/renderer_platform_font_query.c`），只有 `fc-match`
  回显了请求的 family 才接受，弱别名（没有 Arial 的宿主上 Arial 解析成
  Nimbus Sans）像 Skia 一样被丢弃。全部候选都没命中时仍回退到通用角色查询，
  字体集不标准的宿主照常出字。
- **代价**：探测每个进程解析一次，与 weight bucket 同批；face 注册与字形
  缓存未变。
- **门禁证据**：CI 字体环境下 `avg 3.36%` / `worst 8.50%` 降到
  `avg 1.19%` / `worst 2.61%`（限制 `3.00%` / `10.00%`）。最差的几格：
  `checkbox/dark/focused 8.50 → 2.55`、`checkbox/light/default 8.19 → 2.21`、
  `text_field/light/default 3.85 → 2.61`、`text_field/dark/default 3.93 → 2.58`。
  阈值、门禁、候选表都没有被放宽或重排。

## 升级说明

- 更新依赖即可，没有新增或删除公开符号，包边界与协议未变。
  `wzzc-dev/window` 的 pin 与 `0.7.0` 相同。
- 在通用 `sans-serif` 解析到「不在 Skia 候选表首位」的 Linux 宿主上（装了
  Noto 的桌面很常见），Sun 现在画的是 Skia 画的那个 family；这些宿主的
  文本度量会有轻微变化，这是修复本身，不是回归。
- 自带并注册字体的 app 不受影响：候选表只喂默认的平台字体发现路径。
