# Plan: MoUI Studio 右栏改成 VS Code 侧栏（分页 + 圆角输入卡）

- **Status**: active（实现完成，待真机逐项复查收尾）
- **Date**: 2026-10-13
- **Related**: `docs/plans/active/moui-studio-right-panel-vscode-form.md`（上一轮，
  本方案**推翻其两条明确非目标**）、`docs/plans/active/moui-studio-shell-completion.md`
  （app 四项预算棘轮 + ADR 0039/0040）、`memories/repo/moui-studio.md`（右栏头两个
  ✕ 的语义分工）
- **Goal**: 把右栏从「面板头 + 6 页签 + 单一滚动区 + 钉底 composer」改成**分页的
  VS Code 侧栏**——检查器页与 AI 页分开，AI 页带圆角描边输入卡与卡下状态行；
  同时修掉真机复查中发现的四个可见缺陷。
- **Non-goals**: 不动 `ai_workspace_panel`（PsAi 右栏的更改/文件面板）；不动
  `ai_center`（PsAi 中心会话面）；不动左栏/顶栏/底栏/状态栏；不新增
  `@style.IconName` 字形；不做分区折叠状态机（第二级折叠仍延后）。

> 触发：用户三图对比——参考图是 VS Code 右侧聊天侧栏（面板头动作簇 + 圆角输入卡
> + 卡下 Autopilot 状态行），并明确两点诉求：**「把这六个页签算一页，AI 算新的一页」**、
> **「默认宽一点，UI 再美化一点」**。

## 真机复查修掉的四个缺陷（用户报的「字还有没显示的」）

这四个都是**只有真机才显形**的——面板级 `draw_commands` 断言当时全绿。

| # | 缺陷 | 根因 | 修法 |
|---|---|---|---|
| 1 | 转录长文本被右缘切掉 | `ai_transcript` 把**外宽**传给 `timeline_rows`，而滚动区被 `padding_edges` 收到 `width − 24`——每行比自己的裁剪区宽 24pt，被 flex 居中后整体右移 12pt | 行按 `inner` 构建（宽与裁剪区同源） |
| 2 | diff 长代码行被硬切（无省略号） | `@views.text` 的宽是**最小值**（布局取 `max(声明宽, 实测宽)`），长行自己长宽越过裁剪区 | `diff_row` 走 `fit_label` 截断 |
| 3 | 卡标题把「已处理」徽标顶出面板（显示成「已处」） | 标题写死预留 70pt，而徽标实测约 40pt、标题可任意长 | 徽标宽按内容算，标题宽 = 行宽 − 徽标宽 − 间距，再 `fit_label` |
| 4 | 生成成功后「正在生成提案…」永远转圈 | 忙碌占位卡是**进行中**的瞬时状态，但「提交后、回执前」存盘会把未结算卡写进 JSON，下次启动读回来就永久转圈 | 恢复路径新增 `drop_in_flight_cards`（摘掉**无内容**的未结算计划卡与空流式卡；有内容的未结算卡原样保留） |

另外三处预算缺陷（同一轮）：

- **钉底块夹取错位**：早先对整块取 `min(220)`，于是「输入卡 + 状态行」的固定
  部分**也会被削掉**——待审计卡在场上时 `natural` = 224 > 220，被削掉的正是最底下
  那条状态行。改为**固定段全额 + 决策条封顶**（`AI_DECISION_MAX_HEIGHT`）。
- **卡片内衬漏进预算**：卡片化新增的卡内衬 12pt 没进 `ai_docked_height`，状态行
  被顶出面板（本仓的「双算账」复发形态）。现在每一段都走具名常量。
- **提示浮层过大**（`moui/views`，用户报的「小 tips 弹出的现在有点太大了」）：
  `@views.tooltip` 把文字塞进固定 `180×24` 的框、再套 `Raised` 容器——而
  `Raised` 的 `padding` 是 `spacing_scale.lg = 16`（四边各 16），于是一个三字
  提示（「检查器」）渲染成 **212×56**，比它指向的图标还大。改为**按内容定尺寸**
  （ASCII 7.9 / 全角 13.0 估宽 × 1.15 余量 + 6/3 内衬 + 4pt 圆角，底色取主题的
  `Overlay` 面），并新增一条回归（**破断验证过**：还原成 212×56 会红）。

## 视觉调整（用户「搭配不好看」）

| 项 | 前 | 后 | 理由 |
|---|---|---|---|
| `ide_editor_background`（画布底） | L≈12.5% | L≈15.1% | 与面板的明度落差 5.3pt → **2.7pt**：旧值在暗色下读作「纯黑画布 + 灰面板」两块硬拼；现在落差仍在（层级不丢）但读作同一套石墨色的相邻两档 |
| `ide_selection`（选中/气泡底） | H≈204（偏青） | H≈214 | 中性底与强调蓝都在 H≈216–223，旧值是个**第三种色相**——选中行/气泡/页签激活底全用它，画面上于是有「蓝 + 青 + 灰」三套色。现在与强调蓝同族（色相差 15° → **6°**） |
| `RIGHTBAR_WIDTH`（默认宽） | 272 | **340** | 272 是「只有属性字段」时代的宽度；分页后这一栏还要装会话转录（气泡/卡片/diff），那些内容的自然宽度远大于表单字段 |

## 决策记录

| 决策 | 理由 |
|---|---|
| 六页签合并为一页，AI 另起一页 | 用户明确要求；两者是**不同对象**（检查器的切面 vs 聊天会话），同一页里并置时检查器要为聊天让出常驻高度 |
| 输入面**只在 AI 页**（检查器页不画） | 严格 VS Code 口径（用户选）；代价是「选中控件后想问 AI」要先切页——用**对象条**（检查器页）与**上下文芯片**（AI 页）同源显示当前对象来补偿 |
| 对象身份从头部下移到正文首段 | 头部要让位给页块切换器；且「清空选中」与「关闭面板」必须在**不同的带**（2026-09-30 事故的结论） |
| 切页器用页块（tile）而不是第七个页签 | 页块表达「我在哪个视图」，与页签行（「同一对象的哪个切面」）是两层不同的东西；VS Code 侧栏正是这个结构 |
| 不动 `RvWorkspace` | 那是**另一个产品面**（审阅 agent 改动），不属侧栏分页体系 |
| 页块降级为图标 only | 窄窗紧急档 170pt 放不下两个带标签页块；语义（tooltip/无障碍标签）保持完整页名 |
| 卡片底用 `ide_elevated()`，不用 `palette.surface` | 后者是 ambient 回落色，钉底带内出现它正是既有回归要抓的缺陷形态；两色在两种主题下都不相等，断言与语义同时成立 |
| 状态行在卡**外** | 它是「这轮对话处于什么闸门状态」的面板级读数，不是输入的一部分；放卡外也不会让卡片高度随待审计数跳变 |
| 默认宽 272 → 340 | 用户要求；272 是表单字段时代的宽度，装不下转录内容的自然宽度 |

## 风险与未决

1. **结构变化覆盖了既有回归网**：改写后的用例在旧实现上会红——需要真机复查补足
   （本轮已做四轮）。
2. **`/tmp/winlist` 与 MCP 走查脚本不在 repo**：真机截图与切页无法脚本化复现。
   建议下一步把窗口枚举 + 截图收成 repo 内的小工具（见「验收」节）。
3. **两页的键盘可达性未做**：页块切换目前只有指针与命令面板入口，没有
   `StudioCommand` 键位；AI 页的会话管理动作（＋/置顶/删除）也没有快捷键。
4. **`ide_selection` 是共享色**：它同时服务树行选中（左栏）、页签激活底
   （`RvWorkspace`）与用户气泡。本轮只调色相，未拆分角色——若后续要让气泡
   独立于「选中」语义，应新增一个 `ide_bubble()` 而不是继续共享。
5. **`@views.tooltip` 的 API 变更**：新增可选 `theme?` 参数（向后兼容）。
   提示浮层的底色现在取主题的 `Overlay` 面——**亮色主题下的观感未做真机复查**
   （本轮只在暗色下验证）。
6. **默认宽 340 是折中**：更宽会让 1280 窗的中心工作区变窄（当前中心约 640）。
   用户在窄屏上若觉得拥挤，可拖 sash 或后续按窗口宽做自适应默认值。
