# Plan: moui-support upstream workspace migration

- **Status**: done; compatibility release published and default workspace restored
- **Scope**: Upgrade the `window` submodule's `moui-support` branch to the
  upstream `modules/window` and `modules/windowing` workspace layout, then
  make MoUI resolve that layout in local development mode.

## Decision

`moui-support` keeps the public `wzzc-dev/window` module name. The independent
raw-handle contract remains the canonical `Milky2018/windowing` module, exactly
as upstream publishes it; the former nested `wzzc-dev/window/windowing`
subpackage is retired. The directory layout, package boundaries, and workspace
membership match upstream. Upstream proposal branches retain the canonical
`Milky2018/window` module name; MoUI must not mix those window/event nominal
types with the fork-facing package identity.

## Acceptance

- [x] Preserve the existing `moui-support` commit as a recovery branch before
  changing the branch tip.
- [x] Place all window source packages beneath `modules/window/` and the raw
  handle contract beneath `modules/windowing/`; no root `moon.mod` remains.
- [x] Preserve MoUI-specific desktop, Web, mobile, and WeChat behavior,
  including the hosted mobile/fullscreen changes omitted from the upstream PR
  integration branch.
- [x] Change `moon.work` and `scripts/window-dev-mode.sh` to add/remove the
  two nested window modules, never `./window`.
- [x] Keep MoUI on the `wzzc-dev/window` event/window type graph, use the
  shared `Milky2018/windowing` raw-handle contract only at FFI boundaries, and
  validate a local Showcase macOS build plus focused window package tests.
- [x] For every legacy source, native stub, template, example, and test beneath
  the former package roots, retain it under the corresponding `modules/window/`

- [x] Use upstream macOS source as the baseline and retain only the isolated
  system-menu extension (`SystemMenuDescriptor`,
  `SystemMenuItemDescriptor`, and menu-action callbacks) as an upstream
  contribution candidate; remove the `moui_macos_smoke` example.

## Legacy Parity Audit

Baseline: `codex/moui-support-legacy` at `2723fb9ccbf352bc4551c0e9db66747e25ea5ed7`.

The audit maps the former package roots (`android`, `core`, `dpi`, `examples`,
`harmonyos`, `ios`, `linux`, `macos`, `web`, `wechat`, `windows`, and
`windowing`) into the two nested modules. It must distinguish intentional
package metadata/import rewrites from missing source. Non-macOS paths should
retain the legacy implementation and tests; macOS tracks the upstream layout
and API baseline except for the isolated custom system-menu extension required
by MoUI.

## Upstream Contribution Boundary

The custom macOS system-menu extension remains local so MoUI can keep its
native application menu bar. It is intentionally limited to
`macos/menu.mbt`, its three FFI declarations, `native_appkit_menu.m`, and
the package native-stub/header wiring. Submit that focused AppKit API upstream
after its public API shape and callback ownership have been reviewed; do not
combine it with MoUI-specific backend or example changes.

Initial file audit: 340 legacy package files, 240 byte-identical after the
move, 76 rewritten for package metadata, upstream behavior, or generated API
surfaces, and 24 absent at their mapped destination. The actionable absences
are four `moui_*_smoke` example packages, three Linux regression suites, and
three Windows regression suites. The two Wayland generated protocol sources
are reproducibly generated by `modules/window/build.js`; the missing Web
`pkg.generated.mbti` is generated output rather than handwritten source.

Final parity audit: every mapped handwritten legacy file is present. The only
remaining unmapped paths are regenerated `pkg.generated.mbti` files and the two
Wayland protocol C sources generated by `modules/window/build.js`. Linux IME
and monitor state, Windows keyboard/monitor/IME behavior, and the corresponding
non-host FFI fallbacks were restored from the legacy baseline. Windows retains
the newer split `mbw_create_window`/`mbw_set_window_raw_id` ABI while preserving
the legacy MoonBit behavior.
