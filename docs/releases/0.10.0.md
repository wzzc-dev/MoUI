# MoUI 0.10.0 — Partial repaint observability

Minor release since `0.9.2`: all 26 public modules move to `0.10.0` on the
`0.10.x` line. It stays additive — no existing symbol is removed or renamed, no
existing parameter changes, no enum gains a variant, and no package boundary or
host wire contract changes. The Skia renderer now resolves frame damage per
draw target and reports it; `moui dev` and `check` diagnose a stale `dev_hot`
tree before Moon runs; the pinned toolchain moves to `moonc 1.0.0-rc1`.

## Partial repaint

- Damage resolves per draw target instead of forcing a full redraw whenever a
  GPU target exists (`#48`). The retained CPU raster surface and the Metal
  persistent backing accept sub-rect damage after their first full draw; a
  fresh GPU drawable and an unsupported route stay full. Resize,
  incomplete-frame, flush/copy failure, and backing invalidation force full
  reinitialization, and a frame whose command stream still contains push/pop
  scope commands records a full-damage fallback.
- The Metal backing is updated only inside the effective damage region, then
  copied in full into the fresh drawable. Partial presentation stays
  unimplemented and is reported separately, so `partial_present` is `false` on
  every route.
- `SkiaDamageReport` exposes the per-frame requested and effective
  `@core.DamageRegion`, fallback reason, `SkiaDamageTarget` (`RetainedSurface`
  / `GpuBacking` / `GpuDrawable`), presented flag, and draw/copy/present
  microseconds; `SkiaRasterRenderer::last_damage_report()` returns it.
  `SkiaPartialRepaintReport` separates the advertised
  `SurfaceDamageCapability`, drawable retention, persistent backing, partial
  redraw, and partial present, available through
  `SkiaRasterRenderer::partial_repaint_report()`.
- A sub-rect (or empty) request promoted to full emits the
  `renderer.damage_fallback` diagnostic only when the frame did not already
  request full damage; the message carries the reason and the detail records
  the requested and effective kinds.
- The default `raster()` provider and the CPU fallback advertise `SubRect`; the
  GPU provider advertises it only on Metal and normalizes an explicit
  `SubRect` to `FullSurfaceOnly` on the other GPU routes. Multi-frame pixel
  comparisons cover move, delete, transparent background, HiDPI, scope
  fallback, resize, and incomplete-frame recovery, and the cached-layer
  benchmark gains the partial overlay plus draw/copy/present phase timings.

## Stale dev_hot diagnosis

- A `dev_hot/` generated before the standalone-module fix has no
  `moon.mod`/`moon.work` of its own, so Moon attributes its packages to
  `wzzc-dev/moui_devhost` and every check fails package resolution with an
  opaque error. Plain-Node detection (`scripts/lib/dev-hot-artifacts.mjs` plus
  the `scripts/moui-dev-hot-check.mjs` CLI) inspects the generated module and
  workspace manifests, the app dependency, and the manifest format marker,
  then prints the concrete paths with the rebuild/isolate recovery.
- `scripts/check.mjs` runs the detector before any planned step and
  `scripts/moui-dev.mjs` before non-hot builds; native `--hot` still
  regenerates in `prepareHot()`. The generator stamps `generatorFormat: 2`
  while keeping `schemaVersion 1`, so a pre-marker tree is reported as stale
  instead of silently accepted. Regression tests cover regeneration healing,
  idempotent reruns, incomplete artifacts, wrong module names, missing
  dependencies, and the recovery text; the `pr-static` profile runs them.

## Toolchain baseline

- `.moonbit-toolchain` pins `moonc 1.0.0-rc1+3c0520448` (`moon 0.1.20261126`,
  `moonrun 0.1.20261126`); the Playground worker stays at
  `@moonbit/moonc-worker@0.1.202611201`, whose npm latest and integrity were
  unchanged. The migration is warning-only: `Map`/`Set` `add` is deprecated
  for `insert`, `Buffer::write_bytes` for `write_bytesview`,
  `#cfg(target="llvm")` for `target="native"`, legacy stdin JSON in `build.mbtx`
  prebuild scripts for `MOON_*` environment variables, and
  `link.wasm(-gc).exports` for `#export_name`. Native and wasm-gc builds,
  formatting, generated interfaces, and the Playground asset pipeline pass
  with the new pin (`#46`).

## Workflow and Skia stub assets

- The stub-release `workflow_dispatch` description is single-quoted (`#43`):
  the plain scalar contained `: `, which YAML rejects, so GitHub failed the
  workflow before scheduling jobs and the `recipe_sha256` migration rebuild
  never ran. A new offline gate, `node scripts/validate-workflow-yaml.mjs`,
  parses every `.github/workflows/*.yml` with PyYAML in `pr-static`.
- The lock republishes the `dev-6d73578a36` stub archives with their
  `recipe_sha256` recorded.

## Policy

`0.10.0` is a minor on the synchronized `0.10.x` line. The public additions are
new types and methods only, so no breaking change needs the pre-1.0 allowance;
the upgrade notes below record the new surface.

  `moui_skia_renderer`. No existing symbol changes, no constructor gains a
  parameter, and no existing enum gains a variant, so existing apps compile
  unchanged.
- `renderer.damage_fallback` is a new stable diagnostic code. A Diagnostics
  consumer that switches on codes adds one arm when it wants the new signal.

# MoUI 0.10.0 —— 局部重绘可观测性

自 `0.9.2` 以来的次版本：26 个公开模块统一到 `0.10.0`，进入 `0.10.x` 发布线。
仍然只做加法：不删除、不改名既有公开符号，不改既有参数，没有枚举新增 variant，
包边界与宿主协议未变。Skia 渲染器改为按绘制目标解析帧 damage 并上报；
`moui dev` 与 `check` 在启动 Moon 前诊断过期的 `dev_hot` 树；工具链基准升到
`moonc 1.0.0-rc1`。

## 局部重绘

- damage 按绘制目标解析，不再因为存在 GPU 目标就一律整帧重绘（`#48`）。保留的
  CPU raster surface 与 Metal 持久 backing 在首次整帧之后接受 sub-rect damage；
  全新的 GPU drawable 与不支持的路线仍走整帧。resize、未完成帧、flush/copy
  失败与 backing 失效都会强制整帧重建；命令流里仍含 push/pop scope 命令的帧
  记录整帧回退。
- Metal backing 只在有效 damage 区域内更新，然后完整拷贝进新的 drawable。局部
  呈现仍未实现并单独上报，因此所有路线的 `partial_present` 都是 `false`。
- `SkiaDamageReport` 暴露每帧的 requested 与 effective `@core.DamageRegion`、
  回退原因、`SkiaDamageTarget`（`RetainedSurface` / `GpuBacking` /
  `GpuDrawable`）、是否呈现以及 draw/copy/present 微秒，由
  `SkiaRasterRenderer::last_damage_report()` 返回。`SkiaPartialRepaintReport`
  分开报告能力 `SurfaceDamageCapability`、drawable 保留、持久 backing、局部
  重绘与局部呈现，经 `SkiaRasterRenderer::partial_repaint_report()` 取得。
- sub-rect（或空）请求被提升为整帧时，只有在帧本身未请求整帧 damage 的情况下
  才发出 `renderer.damage_fallback` 诊断；message 带原因，detail 记录
  requested 与 effective 类型。
- 默认 `raster()` provider 与 CPU 回退宣告 `SubRect`；GPU provider 只在 Metal
  上宣告，其他 GPU 路线把显式 `SubRect` 归一为 `FullSurfaceOnly`。多帧像素
  对比覆盖移动、删除、透明背景、HiDPI、scope 回退、resize 与未完成帧恢复；
  cached-layer 基准新增 partial overlay 与 draw/copy/present 阶段计时。

## dev_hot 过期诊断

- 在独立模块修复之前生成的 `dev_hot/` 没有自己的 `moon.mod`/`moon.work`，
  Moon 会把它的包算到 `wzzc-dev/moui_devhost` 名下，所有检查都因包解析失败而
  报出难以理解的错误。纯 Node 检测器（`scripts/lib/dev-hot-artifacts.mjs` 与
  `scripts/moui-dev-hot-check.mjs` 命令行）检查生成的模块与工作区清单、app
  依赖与清单格式标记，然后打印具体路径与重建/隔离恢复办法。
- `scripts/check.mjs` 在任何计划步骤之前运行检测器，`scripts/moui-dev.mjs` 在
  非 hot 构建前运行；原生 `--hot` 仍在 `prepareHot()` 里重建。生成器在保留
  `schemaVersion 1` 的同时写入 `generatorFormat: 2`，没有标记的旧树因此被判为
  过期而不是静默接受。回归测试覆盖重建修复、重复运行幂等、残缺产物、错误模块
  名、缺失依赖与恢复文案；`pr-static` 档案会运行它们。

## 工具链基准

- `.moonbit-toolchain` 固定 `moonc 1.0.0-rc1+3c0520448`（`moon 0.1.20261126`、
  `moonrun 0.1.20261126`）；Playground worker 仍是
  `@moonbit/moonc-worker@0.1.202611201`，npm 上的 latest 与 integrity 未变。
  迁移目前只有告警：`Map`/`Set` 的 `add` 建议改用 `insert`，
  `Buffer::write_bytes` 建议改用 `write_bytesview`，
  `#cfg(target="llvm")` 建议改用 `target="native"`，`build.mbtx` 预构建脚本
  旧的 stdin JSON 建议改用 `MOON_*` 环境变量，`link.wasm(-gc).exports` 建议
  改用 `#export_name`。原生与 wasm-gc 构建、格式化、生成接口与 Playground
  资产流水线在新 pin 下均通过（`#46`）。

## Workflow 与 Skia stub 资产

- stub 发布的 `workflow_dispatch` 描述改为单引号（`#43`）：原来的 plain scalar
  含 `: `，YAML 拒绝解析，GitHub 在调度任务前就让 workflow 失败，
  `recipe_sha256` 迁移重建因此从未运行。新的离线门禁
  `node scripts/validate-workflow-yaml.mjs` 在 `pr-static` 里用 PyYAML 解析
  每个 `.github/workflows/*.yml`。
- 锁定文件重新发布了 `dev-6d73578a36` stub 归档，并记录各自的
  `recipe_sha256`。

## 政策
