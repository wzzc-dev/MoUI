# MoUI 0.6.1 — Developer Loop and Input Correctness

Patch release since `0.6.0`. All 25 public modules move to `0.6.1` together on
the existing `0.6.x` release line (ADR 0065; the line does not advance).

The release carries the Phase 1 developer-loop slice (notifications and
permissions on macOS/Android/Web, `moui test`, `moui inspect`, DevTools socket
transport, golden-image gate, release packaging and signing), the macOS frame
pacing and rich-text scroll ownership work, the picker/datepicker presentation
refactor (ADR 0070), and two input-correctness fixes: disabled controls become
inert on direct input, and a non-modal presentation barrier no longer swallows
`Move` (one toast used to disable hover for the whole app).

Most changes are additive. The one public signature break is the app-owned
expanded state on `picker` / `datepicker`; see the migration notes below.

## Developer loop (maturity Phase 1)

- **Notifications and permissions** now run through the window host services
  on all three embedded/browser targets: macOS (`UNUserNotificationCenter`,
  permission refresh, isolated dev bundle identity), Android
  (`NotificationManager`, `POST_NOTIFICATIONS`, JNI bridge), and Web
  (`Notification` API plus permission state). Showcase gains a probe surface;
  matching-device Android evidence remains tracked separately.
- **CLI**: `moui test` plus the 30-minute tutorial, a standalone Web bundle
  fallback packager, bounded `verify` log capture with run manifests, `--release`
  for Android/iOS builds, environment-driven Android release signing, iOS
  device-signing flags with an evidence runbook, and deeper desktop packaging
  (icons, ICU, Web metadata).
- **DevTools**: versioned document, publisher, and `moui inspect`; loopback
  socket transport speaking NDJSON; render diagnostics wired into the runtime
  sink.
- **Golden images**: deterministic render scenes now gate the PR profile.
- `new_world` graduated to its own repository (`wzzc-dev/new_world`).

## Frame pacing and scroll ownership

- `wzzc-dev/window@0.5.4-0.2.9` adds the macOS CVDisplayLink frame source; the
  runtime pumps vsync-driven frames (`MOUI_MACOS_FRAME_PACING=0` restores the
  old timer path). The same window release migrates the remaining `derive`
  declarations, so `moon check` reports zero warnings.
- Rich text unifies scroll ownership in `MarkdownEditorScrollMode`
  (Element/App) instead of three separate knobs, moves transient scroll into
  the element slot, settles once per gesture, and reads the painted offset in
  the indicator. Decorations consume a frame-local scroll snapshot.

## Picker and datepicker (ADR 0070)

- Pickers are no longer layout children: `popup_host` + `PresentationSpec`
  drive open/close as presentation state, so opening no longer dirties the
  parent layout or leaves a stale place cache. Outside tap, Escape, Back, the
  top-most dismissal layer, and the enter/exit ghost come from the shared
  presentation stack.
- Follow-up fixes: a press latch keeps the trigger from reopening on the same
  gesture's `Up` (only `Cancel`/`Exit` clear it), `popup_host_fill` makes the
  trigger fill its parent frame, and `match_anchor_width` aligns the popup with
  the trigger width.

## Input correctness

- **Disabled controls are inert at one enforcement point.** `.disabled()` only
  set `environment.enabled=false`, and only Button/Text inspected it. The
  runtime dispatch funnel now consumes pointer `Down`/`Up` and `Enter`/`Space`
  for disabled subtrees, ignores text/gesture/drop input, and focus traversal
  skips `semantics.disabled` nodes. The per-control Button check was removed.
  `examples/disabled_input_demo` reproduces the contract in both a GUI and a
  headless selftest (`disabled_messages=0 enabled_messages=5`).
- **Non-modal presentation barriers only consume `Down`.** Hoisting a barrier
  as an overlay child made the runtime treat in-flow siblings as covered even
  when the barrier passed the event through, so a single toast killed hover
  across the app. Viewport-sized hosts keep their barrier in-flow (they already
  span the viewport); base-sized popup hosts keep the hoisted barrier so
  outside-tap still reaches beyond the trigger.

## Verification

- PR #15 (barrier and guidance fixes) is green across all 24 checks, including
  the full workspace baseline, PR profile gate, and `moon fmt --check`.
- Local gates: `moui/views` 39/39, `moui/views/presentation` 13/13,
  `moui/runtime` 245/245, popover/navigation/form/controls/smoke suites green,
  plus the static trio, guidance, renderer-capability, and doc-reference
  validators.
- All 25 modules were published to mooncakes at `0.6.1` in dependency order
  (base first), and a scratch consumer module resolves every one of them at
  `0.6.1` and passes `moon check`.

## Upgrade notes

- Update dependencies; no public symbol was removed. `wzzc-dev/window` moves
  from `0.5.4-0.2.7` to `0.5.4-0.2.9` (notification/permission host services,
  CVDisplayLink frame source). Update the window pin together with MoUI.
- **Migration: `picker` / `datepicker` now require app-owned expanded state.**
  Pass `expanded~` and `on_expanded_change~`; the view rebuilds once per
  open/close. Selection still arrives through `on_select` / `on_select`.
- Disabled controls in custom controls no longer receive activation messages;
  if a control relied on observing input while disabled, move that behavior to
  an ancestor that stays enabled.
- Toast/non-modal overlays no longer suppress hover on content beneath them;
  hover-driven inline actions work again with a toast on screen.

# MoUI 0.6.1 — 开发闭环与输入正确性

自 `0.6.0` 以来的补丁版本。25 个公开模块统一到 `0.6.1`，仍然留在 `0.6.x`
发布线（ADR 0065，本版不推进线号）。

本版包含 maturity Phase 1 的开发闭环切片（macOS/Android/Web 通知与权限、
`moui test`、`moui inspect`、DevTools socket 传输、golden 图像门禁、发布打包与
签名）、macOS 帧调度与富文本滚动所有权、picker/datepicker 的 presentation
重构（ADR 0070），以及两项输入正确性修复：disabled 控件在直接输入下真正失效；
非模态 presentation barrier 不再吞掉 `Move`（此前屏上一条 toast 就会让整个
app 的悬停失效）。

绝大多数改动是增量式的。唯一一处公开签名破坏是 `picker` / `datepicker` 的
展开态改为 app-owned，迁移方式见下。

## 开发闭环（maturity Phase 1）

- **通知与权限**在三个 embedded/browser 目标上统一走 window host services：
  macOS（`UNUserNotificationCenter`、权限刷新、隔离的 dev bundle 身份）、
  Android（`NotificationManager`、`POST_NOTIFICATIONS`、JNI bridge）、Web
  （`Notification` API 与权限状态）。Showcase 增加探针；Android 真机证据仍
  单独跟踪。
- **CLI**：`moui test` 与 30 分钟教程、独立 Web bundle fallback packager、
  有界的 `verify` 日志捕获与 run manifest、Android/iOS 的 `--release`、
  环境变量驱动的 Android release 签名、iOS 真机签名参数与证据 runbook，
  以及更完整的桌面打包（图标、ICU、Web 元数据）。
- **DevTools**：版本化 document、publisher 与 `moui inspect`；loopback socket
  NDJSON 传输；render diagnostics 接入 runtime sink。
- **Golden 图像**：确定性渲染场景进入 PR profile 门禁。
- `new_world` 毕业为独立仓库（`wzzc-dev/new_world`）。

## 帧调度与滚动所有权

- `wzzc-dev/window@0.5.4-0.2.9` 增加 macOS CVDisplayLink 帧源；runtime 按
  vsync 驱动帧（`MOUI_MACOS_FRAME_PACING=0` 可回退旧定时器路径）。同一版
  window 完成剩余 `derive` 迁移，`moon check` 已 0 warning。
- 富文本把滚动所有权收敛为 `MarkdownEditorScrollMode`（Element/App），不再
  保留三个旋钮；transient 滚动移入元素 slot，每个手势只 settle 一次，
  indicator 读取实际绘制偏移。装饰层消费帧内滚动快照。

## Picker 与 datepicker（ADR 0070）

- picker 不再作为 layout child：`popup_host` + `PresentationSpec` 把
  open/close 变成纯 presentation 状态，打开不再脏父布局或留下 stale place
  cache。outside tap、Escape、Back、最上层 dismissal layer 与进出场 ghost
  全部来自共享 presentation 栈。
- 后续修复：press latch 防止同一次手势的 `Up` 重新打开（只在
  `Cancel`/`Exit` 清除）；`popup_host_fill` 让 trigger 填满父级分配空间；
  `match_anchor_width` 让 popup 宽度对齐 trigger。

## 输入正确性

- **disabled 控件在单一位置强制失效。** 此前 `.disabled()` 只设置
  `environment.enabled=false`，而只有 Button/Text 读取它。现在 runtime 的
  dispatch funnel 统一消费 disabled 子树的指针 `Down`/`Up` 与
  `Enter`/`Space`，忽略 text/gesture/drop 输入，focus 遍历跳过
  `semantics.disabled` 节点；Button 里的重复检查已删除。
  `examples/disabled_input_demo` 同时提供 GUI 与无头 selftest
  （`disabled_messages=0 enabled_messages=5`）。
- **非模态 presentation barrier 只消费 `Down`。** barrier 被提升为 overlay
  child 后，runtime 即使看到 barrier 放行事件，也会把同点位的 in-flow 兄弟
  视为已覆盖；一条 toast 就足以让全 app 悬停失效。现在 viewport-sized host
  的 barrier 留在 in-flow（host 本就铺满 viewport），base-sized popup host
  仍保持 hoist，保证 outside tap 能触及 trigger 之外的区域。

## 验证

- PR #15（barrier 与 guidance 修复）24/24 全绿，含完整 workspace baseline、
  PR profile gate 与 `moon fmt --check`。
- 本地门禁：`moui/views` 39/39、`moui/views/presentation` 13/13、
  `moui/runtime` 245/245，popover/navigation/form/controls/smoke 全绿，
  静态三件套、guidance、renderer-capability、doc-references 全过。
- 25 个模块已按依赖顺序（base 优先）发布到 mooncakes `0.6.1`；一个临时消费者
  模块能解析全部 25 个 `0.6.1` 依赖并通过 `moon check`。

## 升级说明

- 更新依赖即可，没有公开符号被删除。`wzzc-dev/window` 从 `0.5.4-0.2.7`
  前进到 `0.5.4-0.2.9`（通知/权限 host services、CVDisplayLink 帧源），
  请与 MoUI 一起更新 pin。
- **迁移：`picker` / `datepicker` 的展开态改为 app-owned。** 传入
  `expanded~` 与 `on_expanded_change~`，open/close 各触发一次重建；选择结果
  仍通过 `on_select` 回调。
- 自定义控件在 disabled 状态下不会再收到激活消息；如有依赖「disabled 时仍
  观察输入」的行为，请移到保持 enabled 的祖先节点。
- toast 等非模态浮层不再压制其下方内容的 hover，屏上有 toast 时悬停驱动的
  行内动作恢复可用。
