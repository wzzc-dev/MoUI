# MoUI 0.9.2 — Declarative drag and drop, native dev hot reload

Patch release since `0.9.1` on the `0.9.x` line. It uses the line-level pre-1.0
allowance again: public API is added, but nothing is removed or renamed, no
package boundary or host wire contract changes, and every new parameter carries
a default. General drag and drop promised in the `0.9.1` note lands here; the
rest is native dev hot reload across Linux, macOS, Windows and Web, plus two
Skia stub build fixes.

## Drag and drop

- `@core.DragPayload` (`key`, optional `text`), `DragSource` (`payload`,
  `min_distance` default 4.0), `DropTarget` (`key`, optional `accepts`) and
  `DragDeclaration` give an in-app drag a declarative shape. `View::draggable`
  and `View::drop_target` attach it to an ordinary view, and
  `ViewNode::drag_declaration` is the node-level channel with a default
  implementation, so existing nodes are untouched.
- The runtime owns the primary-pointer gesture: the source fires `Started` only
  after `min_distance`, then every `Moved`; the deepest accepting target is the
  only hovered one (`Entered`/`Moved`/`Left`/`Dropped`); the source observes
  exactly one terminal `Ended` with the accepting target key, or `None` for a
  release outside a target, Escape, and host cancellation.
- `View::dispatch_drag` translates a `ViewDragContext` into a `ViewDragResult`
  (messages plus whether the tree changed), so handlers stay TEA observers and
  a rebuild does not break the session. `.disabled()` suppresses a source or
  target like other pointer modifiers.
- The existing OS file drop (`DragDropEvent` / `View::on_file_drop`) and the
  low-level `on_drag` recognizer are untouched and can stack with the new
  modifiers.

## Native dev hot reload

- Linux joins macOS (`#33`): `moui dev --hot` generates the same bridge host on
  the canonical linux/skia route and links each generation as a PIC-rewritten
  `plugin.so`. MoonBit's runtime C objects are not PIC, so the runner copies
  `plugin.a`, recompiles the runtime members with `-fPIC` and links with
  `-Bsymbolic`/`--whole-archive`; `dlclose` unmaps the image, so Linux also
  drops the macOS re-exec budget. The Linux backend pumps due GLib timer
  sources from its wait hook, so app timers tick under X11 and Wayland.
- Phase 2A carries the full vocabulary over ABI v1 (`#34`): all 28
  `DrawCommand` variants with brushes, shadows, images, clipping, layers and
  paths, the frame clear color, all 10 `AppEvent` and all 8 `TextInputEvent`
  variants, plus `FrameTick` time and delta so the plugin's animation clock and
  timer subscriptions advance. Any workspace app package can be imported
  without editing the devhost module, and the watcher follows the app's local
  dependency closure.
- Platform-owned state crosses the same bridge (`#39`): focused
  `TextInputState` is published every frame so IME focus, preedit and selection
  survive a swap; committed semantics feed the accessibility bridge and
  accessibility actions dispatch into the plugin; platform-view placements and
  overlay bounds are layered onto the host frame, and a swap disposes the
  previous generation's native views before syncing the new ones.
  `HostDriverHooks` exposes those seams to a host backend without replacing the
  runtime.
- Renderer caches reset after a swap (`#37`): `RendererSession::reset_caches`
  and `SkiaRasterRenderer::reset_host_caches` drop image records, retained and
  picture layers with their byte and admission state, shaping and paragraph
  caches, the paint memo and the font-file typeface cache, and bump the image
  lifecycle generation so old completions are ignored. Font files load from
  owned bytes, so rewriting a path cannot SIGBUS a live mapping.
- Web hot reload keeps state (`#38`): `moui dev --web --hot` generates a
  `dev_web` composition root from the app's `web_wasm` entrypoint, rebuilds it
  for wasm-gc and publishes the wasm atomically at `/__moui/app.wasm`; the page
  polls the generation and reloads. A `localStorage` model and transient
  handoff, plus a `pagehide` flush, keeps model, focus, caret and scroll across
  the refresh; the app opts in with `program_with_dev_state()`.
- Windows joins the native path (`#35`): the bridge host links each generation
  as an MSVC plugin DLL over ABI v1 (`link.exe /DLL /WHOLEARCHIVE` with
  explicit `dev_*` exports), uses `LoadLibraryW`/`FreeLibrary`, and keeps the
  conservative 32-swap re-exec budget. `--hot` is accepted for Windows native
  runs from a Developer Command Prompt.
- The Windows dev host gains an offscreen mode (`#40`): `MOUI_HOT_OFFSCREEN=1`
  renders through a CPU-presented `HostSurface` without an HWND, pumps plugin
  frame ticks and injected events, and lets the seven probe smoke legs run on
  Session 0 hosted runners. The windowed default and the `dev_*` bridge ABI are
  unchanged; the hosted windows-latest job passes all seven legs.

## Skia stub builds

- The Linux stub legs install `libfontconfig1-dev`, `libfreetype-dev` and
  `libharfbuzz-dev` before compiling (`#41`). Without them the system
  FontConfig probe fails, the published archive carries only the directory font
  manager, and every consumer loses CJK text. A leg now fails when the archive
  has no `SkFontMgr_New_FontConfig` reference.
- The stub stale check is recipe-aware and line-ending stable (`#42`): a
  separate `recipe_sha256` hashes the release workflow, `build.mbtx` and the
  publish script, `sources_sha256` stays source-only, and `--check` compares
  both. A missing `recipe_sha256` is stale exactly once, for one migration
  rebuild. CRLF is normalized to LF before hashing and `*.cpp`/`*.h` are pinned
  to `eol=lf`, so a Windows checkout fingerprints like an LF tree.
  `workflow_dispatch force=true` is documented as an exceptional recovery
  hatch, not a routine refresh.
- The lock commits republish the `dev-6d73578a36` stub assets after the
  FontConfig install (`#41`) and the recipe-aware fingerprint (`#42`).

## Policy

`0.9.2` uses the same line-level pre-1.0 allowance as `0.9.1`: a patch may add
public API when the same release ships an upgrade note with a migration
example (`checks/compatibility-policy.json`, `docs/compatibility-policy.md`).
No package boundary and no host wire contract changes.

## Upgrade notes

- Update dependencies; all 26 public modules move to `0.9.2` together. The
  `wzzc-dev/window` pin is unchanged from `0.9.1`.
- The drag-and-drop surface is additive: `DragPayload`, `DragSource`,
  `DropTarget`, `DragDeclaration`, `DragPhase`, `DragEnd`, `ViewDragContext`,
  `ViewDragResult`, `View::draggable`, `View::drop_target`,
  `View::dispatch_drag` and `ViewDragResult::message`/`none`. `View::from_node`
  gained an optional `drag?` handler, so existing constructors compile
  unchanged.
- `ViewNode` gained `drag_declaration` with a default implementation, so
  existing `ViewNode` implementations compile unchanged.
- `HostDriverHooks` and `SemanticsSnapshot::from_frame_payload` are new;
  `HostRuntimeDriver::new`, `DesktopNativeHostBackendCore::new`,
  `LinuxHostAppOptions::new` and `MacosHostAppOptions::new` gained optional
  hook parameters.
- `RendererSession::new` gained optional `reset_caches?`;
  `RendererSession::reset_caches`, `ImageResourceLifecycle::reset` and
  `SkiaRasterRenderer::reset_host_caches` are new, and the Skia providers
  `from_env`, `gpu` and `raster` gained an optional `on_session_bound?`
  callback.
- No enum gains a variant, nothing is removed or renamed, and no host wire
  contract changes: existing apps compile without migration.

# MoUI 0.9.2 —— 声明式拖放、原生开发热重载

自 `0.9.1` 的补丁版本，仍在 `0.9.x` 线上。它再次使用线级 pre-1.0 例外：新增
公开 API，但不删除、不改名既有符号，包边界与宿主协议未变，新增参数一律带默认值。
`0.9.1` 说明里承诺的通用拖放在此落地；其余是 Linux、macOS、Windows 与 Web 的
原生开发热重载，以及两处 Skia stub 构建修复。

## 拖放

- `@core.DragPayload`（`key`，可选 `text`）、`DragSource`（`payload`，
  `min_distance` 默认 4.0）、`DropTarget`（`key`，可选 `accepts`）与
  `DragDeclaration` 把 in-app 拖放变成声明式结构。`View::draggable` 与
  `View::drop_target` 把它挂到普通 view 上；`ViewNode::drag_declaration` 是
  节点级通道且带默认实现，既有节点无需改动。
- 运行时拥有主指针手势：只有指针走过 `min_distance` 源才发 `Started`，随后每个
  `Moved` 都发；最深且接受该 payload 的目标是唯一 hover 目标（`Entered`/
  `Moved`/`Left`/`Dropped`）；源只收到一次终态 `Ended`，带上接受目标 key，或在
  目标外释放、Esc、宿主取消时为 `None`。
- `View::dispatch_drag` 把 `ViewDragContext` 翻译成 `ViewDragResult`（消息及
  树是否变化），处理函数保持 TEA 观察者身份，重建不会打断会话。`.disabled()`
  与其他指针 modifier 一样压制源或目标。
- 既有系统文件拖放（`DragDropEvent` / `View::on_file_drop`）与低级 `on_drag`
  识别器未动，可与新 modifier 叠加。

## 原生开发热重载

- Linux 加入 macOS（`#33`）：`moui dev --hot` 在规范的 linux/skia 路线上生成同一
  套桥接宿主，并把每一代链接成 PIC 重写后的 `plugin.so`。MoonBit 运行时的 C
  对象不是 PIC，runner 会复制 `plugin.a`、用 `-fPIC` 重编运行时成员并以
  `-Bsymbolic`/`--whole-archive` 链接；`dlclose` 会解除映射，Linux 因此不再套用
  macOS 的重执行预算。Linux 后端还在 wait hook 里泵送到期的 GLib timer source，
  X11 与 Wayland 下的 app 定时器因而可以走动。
- Phase 2A 通过 ABI v1 携带完整词汇（`#34`）：全部 28 个 `DrawCommand`
  variant（含画刷、阴影、图像、裁剪、图层与路径）、帧 clear color、全部 10 个
  `AppEvent` 与 8 个 `TextInputEvent` variant，以及 `FrameTick` 的时间与
  delta，使插件的动画时钟和定时器订阅继续推进。任意 workspace app 包都可导入，
  不必改 devhost 模块；watcher 跟随 app 的本地依赖闭包。
- 平台自有状态走同一座桥（`#39`）：每帧发布聚焦的 `TextInputState`，IME 焦点、
  preedit 与选区在换代后保留；已提交语义喂给无障碍桥，无障碍动作可派发进插件；
  平台 view 位置与 overlay bounds 叠加到宿主帧，换代时先销毁上一代原生 view
  再同步新位置。`HostDriverHooks` 把这些接缝暴露给宿主后端，无需替换运行时。
- 换代后重置渲染器缓存（`#37`）：`RendererSession::reset_caches` 与
  `SkiaRasterRenderer::reset_host_caches` 丢弃图像记录、retained/picture
  图层及其字节与准入状态、排版与段落缓存、绘制 memo 和字体文件 typeface
  缓存，并提升图像生命周期代号，旧完成回调因此被忽略。字体文件从自有字节加载，
  重写同一路径不会再 SIGBUS 活动映射。
- Web 热重载保住状态（`#38`）：`moui dev --web --hot` 从 app 的 `web_wasm`
  入口生成 `dev_web` 组合根，按 wasm-gc 重建，并把 wasm 原子地发布到
  `/__moui/app.wasm`；页面轮询代号并刷新。`localStorage` 的 model 与 transient
  交接加上 `pagehide` flush，让 model、焦点、光标与滚动跨刷新保留；app 通过
  `program_with_dev_state()` 选择加入。
- Windows 加入原生路线（`#35`）：桥接宿主把每一代链接成 ABI v1 上的 MSVC 插件
  DLL（`link.exe /DLL /WHOLEARCHIVE`，显式导出 `dev_*`），用
  `LoadLibraryW`/`FreeLibrary`，并保留保守的 32 次换代重执行预算。在 Developer
  Command Prompt 下，Windows 原生运行接受 `--hot`。
- Windows 开发宿主新增离屏模式（`#40`）：`MOUI_HOT_OFFSCREEN=1` 通过
  CPU 呈现的 `HostSurface` 渲染，不需要 HWND，泵送插件帧 tick 与注入事件，
  让七段探针 smoke 在 Session 0 托管 runner 上运行。有窗口的默认路径与
  `dev_*` 桥 ABI 未变；windows-latest 托管任务已通过全部七段。

## Skia stub 构建

- Linux stub 分支在编译前安装 `libfontconfig1-dev`、`libfreetype-dev` 与
  `libharfbuzz-dev`（`#41`）。缺了它们，系统 FontConfig 探针为假，发布归档只剩
  目录字体管理器，所有消费者丢失 CJK 文本。现在归档若没有
  `SkFontMgr_New_FontConfig` 引用，该分支直接失败。
- stub 过期检查改为配方感知且行尾稳定（`#42`）：独立的 `recipe_sha256` 哈希
  发布 workflow、`build.mbtx` 与发布脚本，`sources_sha256` 只哈希源码，
  `--check` 两者都比。缺失 `recipe_sha256` 只判一次过期，用于一次迁移重建。
  哈希前把 CRLF 归一为 LF，并把 `*.cpp`/`*.h` 固定为 `eol=lf`，Windows checkout
  与 LF 树指纹一致。`workflow_dispatch force=true` 记录为异常恢复口，不是日常
  刷新手段。
- 锁定提交在 FontConfig 安装（`#41`）与配方感知指纹（`#42`）之后重新发布了
  `dev-6d73578a36` stub 资产。

## 政策

`0.9.2` 沿用与 `0.9.1` 相同的线级 pre-1.0 例外：补丁可以新增公开 API，前提是
同一版本附带升级说明与迁移例（`checks/compatibility-policy.json`、
`docs/compatibility-policy.md`）。包边界与宿主协议未变。
