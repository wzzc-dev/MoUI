# HarmonyOS 完全打通 GPU 直出（eglSwapBuffers）

## 目标

真·GPU 上屏：**Skia 画到 `OHNativeWindow` EGL backbuffer → `eglSwapBuffers`**，全程无 CPU readback、无 `present flushed native window` 像素 blit。  
Sticky raster **仅作失败恢复**，成功路径不得触发。

### 成功标准（HVD `component_gallery`）

| 检查 | 期望 |
|---|---|
| configure | `skia-gpu-native` + `egl-gpu` + `gpuAvailable=true` |
| route diagnostics | `present_kind=host-gpu-surface`（不是 `cpu-pixel-frame`） |
| **不得出现** | `sticky fallback to raster` / `present flushed native window` |
| 画面 | 中心非黑、进程 ≥12s、无新 `THREAD_BLOCK_6S` |
| smoke | 至少 `partial` + L2 GPU；服务全绿则冲 `passed` |

**不算打通：** 仅 configure 选中 GPU，但实际 `present flushed`（当前状态）。

---

## 根因（按优先级）

### P0 — `GrBackendRenderTargets::MakeGL` 参数顺序反了

Skia：`MakeGL(width, height, sampleCnt, stencilBits, glInfo)`  
HostGpu 现状（两处）：

```cpp
// skia_stub_surface_image_data.cpp ~2827, ~2944
MakeGL(width, height, actual_stencil, actual_samples, fb_info)
// 默认 sample=1, stencil=0 → 实际变成 sampleCnt=0, stencilBits=1（非法）
```

Worker 已正确用 `MakeGL(w,h,0,0,…)`（`skia_stub_gpu_worker.cpp:1558`）。

### P0 — Origin 与 worker 矛盾

| 路径 | Origin | 注释结论 |
|---|---|---|
| HostGpu 主路径 | **强制 BottomLeft** | “TopLeft 会黑” |
| Worker | **TopLeft** | “BottomLeft 在 HVD 黑” |

同一 XComponent 上两边说法相反；HVD 上 worker 注释更可信。应对齐 **TopLeft**，并加一次 A/B 日志确认。

### P1 — sticky 过宽 + EGL 未先释放

- 任意 `presented=false`（含 incomplete draw）就 sticky → 永久降级  
- `dispose` 不毁 EGL surface，raster 与 EGL 抢同一 `OHNativeWindow`  
- 缺 draw 前 `eglMakeCurrent`、缺 `eglSwapInterval`

## 实现计划

### 1. 修 HostGpu wrap 参数（必做）

**文件：** `moui_skia/native/skia_stub_surface_image_data.cpp`

- `egl_window` + `egl_present_and_acquire_next` 两处：
  - `MakeGL(width, height, actual_samples, actual_stencil, fb_info)`
  - stencil clamp 到 `{0,8,16}`（默认 FBO 用 **0**）
  - wrap origin → **`kTopLeft_GrSurfaceOrigin`**（与 worker 一致）
- create 后：`eglSwapInterval(display, 1)`
- present 前已有 MakeCurrent；在 `flush_and_submit` 或 draw 入口：若 `host_present_handle` 为 EGL window，**强制 MakeCurrent(window)**
- 保留：handle 转移前清空旧 wrapper、OHOS `SET_BUFFER_GEOMETRY`/`SET_FORMAT`/`SET_USAGE`

### 2. 收紧 sticky + 释放 EGL 后再 raster

**文件：** `moui/backend/harmonyos/skia/harmonyos_skia_provider.mbt`  
（可选）`moui/render/skia/renderer_image.mbt` dispose

- sticky **仅**在：`PresentFailed` / `SurfaceUnavailable` / `ensure_gpu_window` 失败  
  **不要**因 incomplete draw 降级
- fallback 前：显式 drop window surface / `eglDestroySurface` / 清 `host_present_handle`（或 renderer dispose 真正释放 surface+context）
- 日志：
  - 成功：`route diagnostics … present_kind=host-gpu-surface`
  - 失败：`HostGpu present failed; reason=…`
  - sticky：现有文案保留

### 3. 可观测性（证明“真直出”）

- 每帧成功路径 **禁止** 调用 `harmonyos_present_skia_pixels_to_surface`  
- 可选：EGL present 成功时 hilog `egl present ok swap=1 w=… h=…`（与 `present flushed` 区分）
- smoke 后 grep：
  - 要有：`present_kind=host-gpu-surface` 或 `egl present ok`
  - 不要有：`present flushed` / sticky

### 4. 验证（HVD，单独跑，不并行 Android）

```sh
scripts/build-mobile-harmonyos-hap.sh --app component_gallery --renderer auto
# install + 启动，≥12s
hdc … hilog | rg 'configure|route diagnostics|egl present|sticky|present flushed'
# 截图中心非黑
node scripts/record-mobile-runtime-smoke.mjs --platform harmonyos --app component_gallery --device <target>
```

若 TopLeft 仍黑、BottomLeft 有图：用运行时一次 A/B（首帧 TopLeft 失败再试 BottomLeft），写死胜出者并记 ADR/session 一句。

### 5. 文档（验证通过后）

- `docs/harmonyos-support.md`：L2 从「configure 可行」升级为「**host-gpu 直出已验证**」；写清证据 grep  
- 可选 session：`docs/ai-sessions/2026-07-15-harmonyos-gpu-direct-present.md`
