# MoUI 0.7.0 — Linux frame clock, Sun parity, window chrome

Minor release since `0.6.2`. All 26 public modules move to `0.7.0` together on
a new synchronized release line (`0.7.x`, ADR 0065); workspace pins follow.

This release carries the Linux monotonic animation clock (PR #28), the Sun ↔
Skia interaction/visual parity program across macOS, Windows, and Linux,
view-declared cursors plus window chrome controls (issues #24/#25,
`wzzc-dev/window@0.5.4-0.2.13`), the p5 canvas graphics extension, the
`moonc 0.10.22` toolchain pin with `build.mbtx` prebuild hooks and published
Skia stub assets, and the `moui package` fixes that make a `cmd/<platform>`
project layout package directly.

## Linux animation clock (PR #28)

- The Linux host installs a real `CLOCK_MONOTONIC` frame clock
  (`linux_frame_clock`), so runtime motion durations are wall-clock time
  instead of a fixed 16 ms step per painted frame. A 180 ms transition no
  longer stretches to seconds on a CPU-rastered window; the step is opt-out
  via `LinuxHostAppOptions::new(frame_clock=None)` for deterministic frame
  stepping in tests and benchmarks.
- The clock is exposed to MoonBit through one C shim plus a wbtest that proves
  monotonicity; the backend host wires it into the runtime clock port.

## Sun ↔ Skia parity

- **Platform font discovery**: Linux reads Fontconfig faces so Sun draws
  vector text instead of falling back to blank/box glyphs; macOS resolves
  faces by CSS weight; Windows enumerates system fonts for the Sun raster
  renderer.
- **Text stack**: CJK fallback on macOS (lazy `ttcf`/`true` sfnt parsing, Arial
  Unicode 344→7 ms and Songti 63 MB 14 ms), Segoe UI Symbol fallback on
  Windows, single-line text centred on the face metric span, fallback spans
  sharing the primary ascent (mixed CJK/Latin baselines within one device
  pixel), and offscreen `moui screenshot` now lays out with the renderer text
  system.
- **Text geometry**: text origin, shader space, and DPR blur/shadow geometry
  align with Skia; dotted stroke tests moved out of the canvas shape suite.
- **Raster hot paths**: rounded rectangles rasterised through analytic row
  coverage (no per-corner shader), the macOS IOSurface presenter, and scratch
  buffer reuse cut CPU raster cost; slider drag on a ~1200-command page now
  runs at 13.5 ms p50 / 73.9 fps release, within one refresh of the Skia GPU
  route (11.3 ms / 87.6 fps).
- **Visual parity gate**: `node scripts/visual-parity-gate.mjs` measures the
  `{default, hover, pressed, focused, disabled} × {light, dark}` matrix against
  Skia and is blocking at avg ≤ 3% and worst ≤ 10%; the `Sun/Skia visual
  profile` job runs it on every PR.

## Window chrome and cursors (issues #24, #25)

- **Cursors**: `CursorStyle` (`Inherit | Default | Icon`) with a neutral
  34-variant `CursorIcon` set and `View::cursor`. The runtime resolves the
  style through the hit chain (overlay order, clipping, ancestor inheritance),
  freezes it during a press/drag, and resets on leave/unmount; each window
  dedupes via a cursor session and projects unsupported shapes to the arrow
  without a capability probe.
- **Window requests**: `WindowRequest` gains `Maximize`, `Restore`,
  `SetFullscreen`, and `SetDecorations`; queue and command facades gain the
  matching helpers. `WindowRecord` records observed maximize/fullscreen state
  independent of focus, and `WindowSurfaceActions` gains
  `set_maximized`/`set_fullscreen`/`set_decorations`.
- **Observed maximize state**: the host now reports
  `@backend_host.Event::MaximizedChanged(Bool)`, so compositor shortcuts,
  tiling gestures, CSD requests, and double-click all converge on one observed
  state; `controls.maximized()` and the CSD restore glyph cannot diverge.
- **Linux CSD titlebar**: `LinuxTitlebarPolicy` drives slot metrics, paint,
  hit testing, and insets from one instance; buttons track hover/press with
  vector glyphs (bar, square, restore pair, X) and a restore glyph when
  maximized; the palette follows the system light/dark scheme.
  `WindowControlSource` mirrors the titlebar occupancy so app chrome can lay
  out against the CSD band.
- **Wiring safety**: an unwired composition root now gets a backend-owned
  fallback request queue instead of the no-op unavailable port, so
  `WindowControlSource` intents and CSD clicks are no longer silently dropped;
  `examples/chrome_demo` is the runnable evidence for both issues.

## p5 canvas

- Renderer-neutral `PushPathClip`/`PopPathClip` with a documented
  bounding-box fallback on non-Skia backends.
- Optional `TextRun` stroke fields (stroke-under-fill on Skia),
  `BlendMode::Source` plus seven advanced separable modes, an offscreen
  `RgbaImage` buffer, and `StrokeCap`/`StrokeJoin` path hints.
- Raw `on_pointer`/`on_key`/`on_keyboard_input` observers and a wasm
  `CanvasRasterizer` ship with the p5 sketch example.

## Build, toolchain, and CI

- The toolchain pins `moonc 0.10.22+124d61d05`; every module prebuild hook
  moved to a `build.mbtx` script so nested moon runs get their own cache,
  target dir, and TMP.
- Skia stub assets are published from MoUI releases for macOS x64, Linux, and
  Windows (`dev-6d73578a36`), with a GitCode mirror and verified fallback; the
  linker receives the stub archive itself, and the lock is refreshed as
  `wzzc-dev`.
- CI moved the remaining jobs to Node 24 releases of `checkout`,
  `cache`, `upload-artifact`, and `github-script`; the renderer capability
  consistency check runs on `pr-native`; the Linux pr-static job installs the
  Wayland prebuild set; the Windows stub header fetch uses the PowerShell
  provider.

## CLI and packaging

- `moui package` resolves `cmd/<platform>` entrypoint packages (alongside the
  root-level `<platform>[_skia|_wgpu|_sun]` names), so a `cmd/linux` layout
  packages with `moui package linux .` directly.
- Build artifact lookup falls back from `moon.work` to the enclosing
  `moon.mod`, removing the need for a scaffolding `moon.work` in a plain
  single-module project.
- The generated `.desktop` uses the app name for `Exec`/`TryExec` (not the
  package leaf name), so an installed entry point resolves; native release
  bundles are stripped with `strip`, taking a ~30.6 MB binary from ~34.5 MB.

## Verification

- The `0.6.2 → 0.7.0` range includes PR #26 (cursors and window chrome) and PR
  #28 (Linux frame clock), plus the Sun parity series.
- Local gates: `moon test moui_cli --target native` 229/229, `moon fmt moui_cli`,
  `generate_repo_docs --check`, and `check-generated-interfaces.mjs` pass on

- `moui package linux .` was run for real on a MoSpace copy with a
  `cmd/linux` entrypoint: exit 0, an X11 window opens at 1280x800 from the

  `outputKind=native-bundle`, `executable=MoSpace`. `linux .`, `linux cmd`,
  and `linux cmd/linux` all produce the same bundle without a `moon.work`.
- CI on `dev` (`44877471184`, run before the release branch): 6 of 9 jobs
  green. The three red jobs are pre-existing on `dev`, not caused by this

  limits on `dev`, in the earlier baseline run), and `PR profile gate` on

  regenerating the facts and interfaces; the parity threshold and the source

- Registry publication: all 26 public modules were published to mooncakes at

## Upgrade notes

- Update dependencies; no public symbol was removed. `wzzc-dev/window` moves
  from `0.5.4-0.2.11` to `0.5.4-0.2.13` (observed maximize state, CSD button
  forwarding, IME surrounding text); update the window pin together with MoUI.
- The release line advances from `0.6.x` to `0.7.x` (ADR 0065); workspace pins
  and the release-closure checks move to `0.7.0` together.
- New APIs are additive: `CursorStyle`/`CursorIcon`, `View::cursor`, the new
  `WindowRequest` variants and surface actions, `WindowControlSource` chrome
  insets, and the p5 path-clip/stroke/blend-mode surface. Existing apps compile
  unchanged; a view without a cursor declaration keeps the platform default.
- `moui package` now finds `cmd/<platform>` entrypoints and falls back to
  `moon.mod` for the build root, so a `moon.work` workaround is no longer
  needed. The generated `.desktop` names the app in `Exec`/`TryExec`; existing
  bundles keep working but should be regenerated to get the corrected entry.

# MoUI 0.7.0 —— Linux 帧时钟、Sun 追平、窗口 chrome

自 `0.6.2` 以来的次版本发布。26 个公开模块统一到 `0.7.0`，同步发布线由
`0.6.x` 推进到 `0.7.x`（ADR 0065），workspace pin 一并更新。

本版包含 Linux 单调动画时钟（PR #28）、macOS/Windows/Linux 上的 Sun ↔ Skia
交互与视觉追平、视图声明的 cursor 与窗口控制（issue #24/#25，
`wzzc-dev/window@0.5.4-0.2.13`）、p5 canvas 图形扩展、`moonc 0.10.22`
工具链 pin 与 `build.mbtx` prebuild、已发布的 Skia stub 资产，以及让
`cmd/<platform>` 工程布局可以直接打包的 `moui package` 修复。

## Linux 动画时钟（PR #28）

- Linux host 安装真实的 `CLOCK_MONOTONIC` 帧时钟（`linux_frame_clock`），
  runtime 的运动时长按墙钟时间推进，而不是每个绘制帧固定 16 ms。CPU 光栅
  窗口上的 180 ms 过渡不再被拉长到数秒；需要确定性步进的测试与 benchmark
  可以用 `LinuxHostAppOptions::new(frame_clock=None)` opt-out。
- 时钟通过一个 C shim 暴露给 MoonBit，并有 wbtest 证明单调性；backend host
  把它接到 runtime 的时钟端口。

## Sun ↔ Skia 追平

- **平台字体发现**：Linux 读取 Fontconfig face，Sun 能绘制矢量文本而不是
  回退成空白/方块；macOS 按 CSS weight 解析 face；Windows 枚举系统字体供
  Sun 光栅渲染器使用。
- **文本栈**：macOS 的 CJK 回退（惰性解析 `ttcf`/`true` sfnt，Arial Unicode
  344→7 ms、Songti 63 MB 14 ms）、Windows 的 Segoe UI Symbol 回退、单行文本
  按 face 度量区间居中、混合 CJK/Latin 的 fallback span 共享主字体 ascent
  （基线差在一个设备像素内），离屏 `moui screenshot` 也改用渲染器文本系统
  排版。
- **文本几何**：文本原点、shader 空间与 DPR blur/shadow 几何和 Skia 对齐；
  dotted stroke 测试从 canvas shape 套件中拆出。
- **光栅热路径**：圆角矩形改用解析式行覆盖率（不再跑逐角 shader）、macOS
  IOSurface presenter、scratch buffer 复用，降低 CPU 光栅成本；约 1200 条
  命令页面的 slider 拖动达到 release p50 13.5 ms / 73.9 fps，与 Skia GPU
  路线的 11.3 ms / 87.6 fps 在一个刷新周期内。
- **视觉 parity 门禁**：`node scripts/visual-parity-gate.mjs` 对
  `{default, hover, pressed, focused, disabled} × {light, dark}` 矩阵与 Skia
  做像素对比，avg ≤ 3%、worst ≤ 10% 为阻塞门禁；`Sun/Skia visual profile`
  job 在每个 PR 上运行。

## 窗口 chrome 与 cursor（issue #24、#25）

- **Cursor**：`CursorStyle`（`Inherit | Default | Icon`）带中性的
  34 个 `CursorIcon`，新增 `View::cursor`。runtime 沿 hit chain（overlay
  顺序、clip、祖先继承）解析样式，按压/拖动期间冻结，离开或卸载时复位；
  每个窗口用 cursor session 去重，不支持的形状回退为箭头且不需要能力探测。
- **窗口请求**：`WindowRequest` 新增 `Maximize`、`Restore`、`SetFullscreen`、
  `SetDecorations`，queue 与 command facade 提供配套方法。`WindowRecord`
  记录观测到的 maximize/fullscreen 状态（与焦点无关），
  `WindowSurfaceActions` 新增 `set_maximized`/`set_fullscreen`/
  `set_decorations`。
- **观测 maximize 状态**：host 上报
  `@backend_host.Event::MaximizedChanged(Bool)`，合成器快捷键、平铺手势、
  CSD 请求与双击现在都收敛到同一个观测状态；`controls.maximized()` 与 CSD
  的 restore 图形不会再和现实不一致。
- **Linux CSD 标题栏**：`LinuxTitlebarPolicy` 用同一份实例驱动 slot 度量、
  绘制、命中测试与 insets；按钮带 hover/press 反馈与矢量图形（bar、square、
  restore 对、X），最大化时切换到 restore 图形；调色板跟随系统明暗方案。
  `WindowControlSource` 镜像标题栏占用，app chrome 可以按 CSD 带布局。
- **接线安全**：没有接线 request queue 的组合根会拿到 backend 自带的后备
  队列，而不是丢弃 push 的 no-op 端口，`WindowControlSource` 意图与 CSD
  点击不再被静默吞掉；`examples/chrome_demo` 是这两个 issue 的可运行证据。

## p5 canvas

- 渲染器中立的 `PushPathClip`/`PopPathClip`，非 Skia backend 有明确的
  bounding-box 回退。
- 可选 `TextRun` stroke 字段（Skia 上 stroke-under-fill）、
  `BlendMode::Source` 与七个 advanced separable 模式、离屏 `RgbaImage`
  buffer，以及 `StrokeCap`/`StrokeJoin` path 提示。
- 原始 `on_pointer`/`on_key`/`on_keyboard_input` observer，以及随 p5 sketch
  示例交付的 wasm `CanvasRasterizer`。

## 构建、工具链与 CI

- 工具链 pin 到 `moonc 0.10.22+124d61d05`；所有模块的 prebuild hook 迁移到
  `build.mbtx` 脚本，嵌套 moon 调用拥有独立的 cache、target dir 与 TMP。
- Skia stub 资产从 MoUI release 发布，覆盖 macOS x64、Linux、Windows
  （`dev-6d73578a36`），带 GitCode 镜像与校验回退；链接器拿到的是 stub
  archive 本身，lock 以 `wzzc-dev` 身份刷新。
- CI 把剩余的 `checkout`、`cache`、`upload-artifact`、`github-script` 迁到
  Node 24 版本；renderer capability 一致性检查在 `pr-native` 上运行；Linux
  pr-static job 安装 Wayland prebuild 集合；Windows stub header 改用
  PowerShell provider 抓取。

## CLI 与打包

- `moui package` 能解析 `cmd/<platform>` 入口包（与根级
  `<platform>[_skia|_wgpu|_sun]` 并列），`cmd/linux` 布局可以直接用
  `moui package linux .` 打包。
- 构建产物查找在找不到 `moon.work` 时回退到上层的 `moon.mod`，普通单模块
  工程不再需要补一个 scaffold `moon.work`。
- 生成的 `.desktop` 用 app 名作为 `Exec`/`TryExec`（不再是包叶子名），装到
  系统后入口可以解析；native release 包会真正执行 `strip`，二进制从约
  34.5 MB 降到约 30.6 MB。

## 升级说明

- 更新依赖即可，没有公开符号被删除。`wzzc-dev/window` 从
  `0.5.4-0.2.11` 前进到 `0.5.4-0.2.13`（观测 maximize 状态、CSD 按钮转发、
