# MoUI 0.3.0

自 `0.2.6` 以来的全部变更。本线核心：**25 个公开模块统一到 0.3.0**、**渲染器直读 `DrawCommand`（删除 PlanOp lowering 与 RenderFrameMailbox）**、**views 过渡设施泛化为 pressable、修复 button-only 遗留**、**HarmonyOS 产品等级升至 `committed`**、**移动端文本 family 渲染修复**，以及一批热路径性能收敛。

本版是 0.2/0.3 线**第一个携带破坏性公开接口变更**的家族版本。依据 [兼容性与生态策略](../compatibility-policy.md)，0.x minor 允许破坏但必须同版携带升级说明与迁移示例——两者分别是 [ADR 0047](../decisions/0047-zero-three-renderer-views-api-retirements.md) 与[视图目录](../view-catalog.md)的 "Pressable transitions and helper dedupe (2026-11-04 migration, 0.3.0)" 段。

**只用标准应用面（`@moui` + 领域 facade + `moui/views` 控件构造器）的应用无需改代码。** 需要迁移的是直接依赖 `render/*` 契约的渲染器作者，以及手写 `views/common` 辅助函数的控件作者。

## Breaking changes（下游必读）

### `moui/render/common`：lowering 与 mailbox 退休

| 已删除 | 替代 |
|---|---|
| `lower_draw_commands` | 渲染器直接匹配 `@core.DrawCommand` 流；保留逐变体穷尽匹配（无 catch-all），新 core 变体保持编译期报错（ADR 0019/0045 的 tripwire） |
| `DrawPlan` / `DrawPlanDiagnostic` | 无——其 diagnostics 没有生产消费者；作用域平衡与能力降级由 `plan_renderer_command_fallbacks`（唯一校验点）与各渲染器自己的 frame report 提供 |
| `PlanOp`（26 变体） | `@core.DrawCommand` 变体本身；plan 阶段只是等 payload 镜像 |
| `RenderFrameMailbox` / `RenderFramePacket` / `RenderFrameMailboxDiagnostics` | `GpuRenderWorker`（本就拥有 sequence/pending/in-flight/control 语义）；其 `submit` 不再复制命令数组 |

`lower_draw_commands` 每帧把 26 个 `DrawCommand` 变体镜像成等 payload 的 `PlanOp` 数组（纯 DTO 拷贝），`RenderFrameMailbox`（222 行）零生产调用者且与 `GpuRenderWorker` 语义重复——两者都是被删除的纯开销([ee0c9681c](https://github.com/wzzc-dev/MoUI/commit/ee0c9681c)、[73b8615cc](https://github.com/wzzc-dev/MoUI/commit/73b8615cc))。wgpu/metal/sun/web 四个渲染器同步改为直读命令流([29ecbd7b4](https://github.com/wzzc-dev/MoUI/commit/29ecbd7b4))；Skia 另获定向图像失效与结构化缓存键([de6c5dcd1](https://github.com/wzzc-dev/MoUI/commit/de6c5dcd1))。

### `moui/views/common`、`moui/views/container`：button-only 过渡设施泛化

| 已删除 | 替代 |
|---|---|
| `ButtonTransitionState` | `PressableTransition`（`Idle` / `Active(PressableState, Double)`） |
| `button_transition_slot()` | `pressable_transition_slot(control~)`，键为 `"moui.views.<control>.transition"`；`button` 保持原有键，wire 编码字节兼容 |
| `button_transition(ctx)` | `pressable_transition(ctx, control="button")` |
| `button_state_with_transition(ctx, prev, next, ms)` | `pressable_state_with_transition(ctx, prev, next, ms, control="button")` |
| `view_button_next_state` | `pressable_next_state`（状态机逻辑不变） |
| `min_view_double` / `max_view_double` | 保留的 `view_min_double` / `view_max_double` |
| `resolve_control_color(fallback, value)` | stdlib `value.unwrap_or(fallback)` |

每个控件现在拥有一个命名空间化的独立过渡槽；`button` 的持久化 `ViewState` 解码不变([1e500a41d](https://github.com/wzzc-dev/MoUI/commit/1e500a41d))。

### `moui_cli` 0.3.1：Web ABI 垫片修正（同线补丁）

`moui_cli@0.3.0` 随家族发布，但其共享的宿主入口垫片仍转发 **8 参** `web_dispatch_pointer_input`，而 `moui@0.2.5` 起该 ABI 已是 **10 参**（`pointer_id` + `pressure`）。0.3.0 发布提交修好了 Studio 的 `sync_versions` 漂移、使导出 bundle 从陈旧的 `moui@0.2.4` 移到 `moui@0.3.0` 后，该不匹配立刻显现：生成的 Web 入口 `moon build --target wasm-gc` 报 *"requires 10 arguments, but is given 8"*。

`moui_cli@0.3.1` 修正垫片、把生成工程默认版本移到 0.3.0 线，并新增回归断言把垫片 arity 与默认 pin 钉在一起；`moui_studio@0.1.4` 随之 pin 0.3.1。**若你已装 0.3.0，请升到 0.3.1。** `--moui-version` 显式指向 0.2.4 及更早的线时，仍需使用旧的 8 参转发。

## 平台

### HarmonyOS：产品等级升至 `committed`

八项 R6 能力在匹配设备上全部实测通过——真实 Skia 首帧经 egl-direct presenter、跨两个 extent 的实时 resize 且无残留鬼影、指针/键盘/滚轮/命名键/修饰符组合、IME 提交、pasteboard 写与（经 ArkTS PasteButton 安全控件）读、accessibility provider 注册并发布 87 个节点、surface 销毁/重建、异步图像状态迁移，证据记录在 [平台矩阵记录](../../checks/platforms/harmonyos.json)([06625fd1f](https://github.com/wzzc-dev/MoUI/commit/06625fd1f)、ADR 0046)。

滚动/拖拽掉帧的实测修复弧([0feac1d70](https://github.com/wzzc-dev/MoUI/commit/0feac1d70))：`active_frame_ms=17` 跨满 60 Hz 周期导致每帧超时、fallback 再睡 17 ms，形成 34 ms 纯等待地板把帧锁在 53 ms 中位数；改为紧轮询后按帧工作速率运行。同时去掉每事件 host-bridge sync（手势在一次 pump 内合并大量事件），并让 a11y pump 按已发布 generation 门控投影。

### Android：段落字体 family 修复

两处渲染缺陷([eccf3565a](https://github.com/wzzc-dev/MoUI/commit/eccf3565a)、[832ffddc8](https://github.com/wzzc-dev/MoUI/commit/832ffddc8))：段落 builder 在 `!defined(__linux__)` 下跳过 `setFontFamilies`，但 Android 的 clang 定义了 `__linux__`（bionic 跑在 Linux 内核上），请求的 family 从未到达 text style，SkParagraph 落到任意 display face——所有标题渲染成小型大写样式。修复还覆盖空 family（映射到 `sans-serif`），并把 CSS 泛型 `system-ui` 映射到 Android 的 `sans-serif` 别名。设备验证：NDK font manager 健康（220 families），修复后标题正常混合大小写。

### Web：path mesh 句柄化

`DrawPath` 以逗号连接的十进制字符串跨越 wasm-gc 边界，而 wasm-gc 无共享线性内存，每个字符都是一次 `string_append_char` import 调用——15 double 的路径顶点约 150 次调用，重复绘制的矢量内容每帧都重付序列化、传输与宿主重解析。CPU profile 显示约 60% 主线程耗在 `wasm-to-js`/`string_append_char`/`pushPathMesh` 而光栅器空闲。现在 `upload_path_mesh` 解析一次并存于句柄后，`draw_path_mesh_cached` 以两个标量回放，`release_path_mesh` 释放；句柄按结构化 `PathSpec` 相等性键控在 256 项有界 LRU 中([9fc284b3a](https://github.com/wzzc-dev/MoUI/commit/9fc284b3a))。

### 依赖

`wzzc-dev/window` 全族升至 **0.5.4-0.2.5**([5bcc50349](https://github.com/wzzc-dev/MoUI/commit/5bcc50349))。

## 性能与热路径

- **段落缓存 LRU**：容量压力原本清空整个缓存（一个大段落驱逐所有），每次 store 还用 `filter` 重建桶数组。现在条目带单调 `last_used` tick，store 逐条驱逐全局最旧项且插入不重建桶([14f245b38](https://github.com/wzzc-dev/MoUI/commit/14f245b38))。
- **runtime 每消息节流**：`sync_commands` 原本每条消息后重建整个 `ActionCommandMap`（含滚动/指针风暴下不变的命令列表）；改为对 `ActionCommand` 列表做指纹，复用 map 仍派发当前模型派生的消息([332f5269b](https://github.com/wzzc-dev/MoUI/commit/332f5269b))。
- **views 主题通道可缓存**：pinned theme 原本把主题相关声明通道降级为 `Uncacheable`（每次 reconcile 变化，清空渲染缓存）；`views_theme_channel` 把 pinned theme 值折进通道键，使这些通道保持 `Exact`，且不削弱失效([3bc541d80](https://github.com/wzzc-dev/MoUI/commit/3bc541d80))。
- **图像生命周期 generation diff**：`RendererSession` 原本每次 `render_frame`/`drain_events` 拉全量图像记录快照并 O(records × pending) 去重；`ImageResourceLifecycle` 现在只在记录集真正变化时推进 generation，session 在 generation 未变时完全跳过拉取与去重([d699459d5](https://github.com/wzzc-dev/MoUI/commit/d699459d5))。
- **ambient theme**：`effective_theme(pinned~)` 成为唯一的 ambient 主题解析点（ADR 0036），替代 21 处手写的 `theme.unwrap_or(ctx.environment.theme)`；所有 16 个 `examples/*/app` 改为单个根 `.theme(app_theme)` 作用域，不再逐控件透传 theme([b1dfd15ad](https://github.com/wzzc-dev/MoUI/commit/b1dfd15ad)、[580a3a893](https://github.com/wzzc-dev/MoUI/commit/580a3a893))。
- **backend 桌面核心共享**：三个桌面后端重复的 13 个字段与近乎相同的构造/建 app 序列收敛到 `DesktopNativeHostBackendCore[W, Extra]`（macOS 63→41 字段、Linux 17→4、Windows 16→3）([548945b28](https://github.com/wzzc-dev/MoUI/commit/548945b28))。
