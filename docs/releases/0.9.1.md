# MoUI 0.9.1 — Semantics roles, inline editing, fallback menu

Patch release since `0.9.0` on the `0.9.x` line. It is the first patch on this
line to add public API: the line-level pre-1.0 allowance lets a patch change
public API when the same release ships an upgrade note with migration examples
(`docs/compatibility-policy.md`). Nothing is removed or renamed, no package
boundary or host wire contract changes, and every new parameter carries a
default. General drag and drop moves to `0.9.2`.

## Semantics roles

- `SemanticsRole` gains `TabList`, `Toolbar` and `MenuItem` (37 → 40 variants),
  so an assistive tree can name a tab strip, a toolbar and a command-menu row
  instead of the generic `Tab`, `Group` and `Label` it had to use.
- They project as `Region` / `Region` / `Label`; the accesskit, macOS and
  Windows bridges and the MCP semantics tag carry `tab_list`, `toolbar` and
  `menu_item`, and the web backend emits `tablist`, `toolbar` and `menuitem`; palette classification treats all three as neutral.

## Inline editing and text selection

- `inline_edit(key~, text~, editing~, on_input~, on_commit~, on_start?,
  on_cancel?, placeholder?)` is a row that shows text and becomes a single-line
  field while `editing`: Enter submits `on_commit(text)`, Escape cancels when
  `on_cancel` is supplied (the default `None` keeps Escape inert), a tap fires
  `on_start`, and an empty idle value shows `placeholder` in the muted colour.
  There is no blur commit — leaving the field is a UI decision the app makes.
- `text_field` gains `on_cancel?` and `key?`, and claims Escape only when a
  cancel message is supplied. `text_field_control`, `controlled_text_field_control`
  and `single_line_text_event` forward them; the search box passes `None`,
  since Escape there belongs to the overlay that owns it.
- `AppRuntime::select_focused_text_all()`, `place_focused_text_caret(offset)`
  and `set_focused_text_selection(start, end)` act on the focused text control.
  A rename prompt can now select the pre-filled name so the first keystroke
  replaces it instead of prefixing it. Offsets clamp and snap to grapheme
  boundaries, and a pure selection change fires no `on_input`.
- `command_menu` gains `on_select_command?`, handing the caller the whole
  `ActionCommand` — label and enabled state included — instead of only its
  `CommandIntent`, because one intent can back several rows.

## Linux context menu fallback

- When the platform menu service answers "unavailable" — on Linux that is the
  `-2` answer when neither zenity nor kdialog is installed — the host renders
  the menu itself: `@views.context_menu_region` over the same command table it
  hands to `ShowMenu`, anchored at the last pointer position, with keyboard
  navigation and Escape dismissal. A headless run shows the menu a desktop run
  shows, so menu paths are capturable in CI.
- The decision keys off the canonical unavailable answer, not
  `capabilities().menus`: a platform that advertises a menu service can still
  fail to show one, while a real dismissal or a greyed command must not open a
  second menu. macOS and Windows keep the native menu.
- `HostOverlay` (`HostOverlay::from_view`) plus `AppRuntime::set_host_overlay`
  let a host mount a layer above the app root without remounting the app
  subtree or changing its element identity. `keeps_focus~ = true` marks the
  layer non-activating, so a press runs its command against the text that
  opened the menu; `AppRuntime::pointer_position()` supplies the anchor.
- `HostRuntimeDriver` gained a private slot that tracks the open menu.

## Policy

`checks/compatibility-policy.json` and `docs/compatibility-policy.md` spell out
the two-stage rule: after `1.0.0` a patch carries fixes and docs only; while
pre-1.0 a patch may change public API when the same release ships an upgrade
note with a migration example. `0.9.1` is the first patch to use that
allowance.

## Upgrade notes

- Update dependencies; all 26 public modules move to `0.9.1` together. The
  `wzzc-dev/window` pin is unchanged from `0.9.0`.
- `SemanticsRole` is an exhaustive enum, so a `match` that covers it must add
  three arms. The in-tree mapping lives in
  `moui/views/common/view_control_helpers.mbt` and the platform bridges:

  ```moonbit
  TabList | Toolbar => Region
  MenuItem => Label
  ```

  An app that keeps its own role table adds the same arms; one that maps roles
  through `@core.SemanticsRole` only (semantics trees, tests) needs the arms in
  the `match` even if the body is a shared fallback.
- `HostRuntimeDriver` was `pub(all)` with public fields only; it now has one
  private field, so a struct literal outside `moui/apphost` no longer compiles.
  Build it through the driver API instead.
- `inline_edit`, the focused-text selection calls, `HostOverlay`,
  `set_host_overlay`, `pointer_position`, and the new optional parameters are
  additive: existing apps compile unchanged, and a `text_field` without
  `on_cancel` keeps its old Escape behaviour.

# MoUI 0.9.1 —— 语义角色、行内编辑、回退右键菜单

自 `0.9.0` 的补丁版本，仍在 `0.9.x` 线上。它是这条线上第一个带公开 API 的
补丁：pre-1.0 期间的线级例外允许补丁改公开面，前提是同一版本附带升级说明和
迁移例（`docs/compatibility-policy.md`）。没有删除或改名既有符号，包边界与
宿主协议未变，新增参数一律带默认值。通用拖放移到 `0.9.2`。

## 语义角色

- `SemanticsRole` 新增 `TabList`、`Toolbar`、`MenuItem`（37 → 40 个 variant），
  辅助树可以点名标签栏、工具栏和命令菜单行，不必再套用 `Tab`、`Group`、
  `Label`。
- 三者分别投影为 `Region` / `Region` / `Label`；accesskit、macOS、Windows
  桥与 MCP 语义标签带 `tab_list`、`toolbar`、`menu_item`，web 后端输出
  `tablist`、`toolbar`、`menuitem`；调色板分类把三者
  都算中性。

## 行内编辑与文本选区

- `inline_edit(key~, text~, editing~, on_input~, on_commit~, on_start?,
  on_cancel?, placeholder?)`：平时显示文本，`editing` 时变成单行输入框。
  回车提交 `on_commit(text)`；给了 `on_cancel` 时 Esc 取消（默认 `None`，
  Esc 保持惰性）；点击派发 `on_start`；空闲态空文本显示 `placeholder`（muted
  色）。不做 blur 提交 —— 离开输入框是 app 自己的 UI 决定。
- `text_field` 新增 `on_cancel?` 与 `key?`，只有给了取消消息才认领 Esc。
  `text_field_control`、`controlled_text_field_control` 与
  `single_line_text_event` 一并转发；搜索框传 `None`，那里的 Esc 归外层弹层。
- `AppRuntime::select_focused_text_all()`、`place_focused_text_caret(offset)`、
  `set_focused_text_selection(start, end)` 作用于当前聚焦的文本控件。重命名
  提示框可以先全选预填名，第一次敲键就是替换而不是前缀。偏移越界会收敛、
  并吸附到字素边界；纯选区变化不触发 `on_input`。
- `command_menu` 新增 `on_select_command?`，把整条 `ActionCommand`（含 label
  与 enabled）交给调用方，而不是只给 `CommandIntent`——同一个 intent 可能对应
  多行。

## Linux 右键菜单回退

- 平台菜单服务回「unavailable」时（Linux 上没装 zenity 也没装 kdialog 时是
  `-2`），宿主自己画菜单：`@views.context_menu_region` 套同一张交给 `ShowMenu`
  的命令表，锚在最后的指针位置，支持键盘走查与 Esc 关闭。无头运行也能看到
  桌面运行看到的菜单，菜单路径因此能在 CI 里取证。
- 判定依据是规范的 unavailable 应答，不是 `capabilities().menus`：声称有菜单
  服务的平台仍可能弹不出来，而真正的取消或灰显命令不能再开第二个菜单。
  macOS 与 Windows 继续走原生菜单。
- `HostOverlay`（`HostOverlay::from_view`）配合 `AppRuntime::set_host_overlay`
  让宿主在 app 根之上一层挂载覆盖层，不重挂 app 子树、不改其元素标识。
  `keeps_focus~ = true` 标记为非激活层，按下时命令仍作用于打开菜单的那段文本；
  `AppRuntime::pointer_position()` 提供锚点。
- `HostRuntimeDriver` 多了一个私有槽位记录当前打开的菜单。

## 政策

`checks/compatibility-policy.json` 与 `docs/compatibility-policy.md` 写明两段式
规则：`1.0.0` 之后补丁只带修复与文档；pre-1.0 期间补丁可以改公开面，前提是
同一版本带升级说明与迁移例。`0.9.1` 是第一个用这条例外的补丁。

## 升级说明

- 更新依赖即可，26 个公开模块统一到 `0.9.1`；`wzzc-dev/window` 的 pin 与
  `0.9.0` 相同。
- `SemanticsRole` 是可穷举枚举，覆盖它的 `match` 必须补三个分支。仓内映射在
  `moui/views/common/view_control_helpers.mbt` 与各平台桥：

  ```moonbit
  TabList | Toolbar => Region
  MenuItem => Label
  ```

  自带角色表的 app 补同样分支；只经 `@core.SemanticsRole` 做映射的 app（语义
  树、测试）也要在 `match` 里补分支，哪怕函数体共用兜底。
- `HostRuntimeDriver` 原本是公开字段齐全的 `pub(all)`，现在多了一个私有字段，
  包外不能再直接写字面量；请走驱动 API 构造。
- `inline_edit`、聚焦文本选区三个调用、`HostOverlay`、`set_host_overlay`、
  `pointer_position` 以及新增的可选参数都是加法：既有 app 无需改动，没传
  `on_cancel` 的 `text_field` 保持原来的 Esc 行为。
