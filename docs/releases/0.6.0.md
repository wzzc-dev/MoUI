# MoUI 0.6.0 — Less Work Per Frame

Feature release since `0.5.2`. All 25 public modules move to `0.6.0` together,
advancing the declared release line from `0.5.x` to `0.6.x` (continuing ADR
0065's synchronized-line policy; the cadence is unchanged, so no superseding
ADR is required).

Four of the six changes in this release remove work the framework did every
frame even though nothing it depended on had changed: re-encoding a declaration
key, repainting the whole surface after a layout move, re-walking a subtree to
derive a payload that was already flat, and rebuilding a scoped child view
because its *parent* model changed. The remaining two are a sizing default and
locale coverage. Each point landed as its own commit with a mutation-sensitive
test that goes red when the optimization is disconnected, exercising the wired
path rather than a helper.

No public signature breaks. The release adds public symbols only (three core
composition-boundary functions and a set of `moui_i18n` localization APIs).
`text()`'s default size is nevertheless an **observable behavior change** (see
below), which is why this lands as a minor rather than a patch under the
compatibility policy.

## Runtime hot paths (three changes, no API surface)

- **Declaration key re-encoding.** Every reused node re-encoded the previous
  side's canonical `DeclarationKey` on each reconcile, even though
  `declaration()` is pure over the stored fields and the previous side does not
  change between two reconciles. `ElementNode` now carries a
  `declaration_cache`, written only at the two sites that assign `view_node`
  (mount and reconcile), halving declaration construction on the steady-state
  path.
- **`layout changed` → full-surface damage.** Layout moves clean subtrees that
  never enter the paint-dirty id set, so any layout pass used to force a full
  repaint to avoid leaving ghosts in the bands they vacated.
  `DamageIndex::placement_changes` now compares screen-space `paint_bounds` and
  overlay fade opacity per element id between the previous and current render
  trees, and unions only the moved ids' old and new bounds into damage.
  `full_damage_reason` is split into an absolute class (structure, environment,
  viewport, activation, exit ghosts — whose paint effect is not expressed
  through position) and a placement class that the move scan may narrow.
- **Retained layers re-walked.** P16 requires the complete payload on the wire
  every frame, so that copy is not optional; what *was* optional is deriving it
  again by walking the subtree. The payload had already been flattened at paint
  time, but the frame builder ignored that and recomposed a transform per
  descendant per frame. Flattening now reuses the frame traversal itself, so the
  replayed bytes are the bytes the walk produced, and the second near-duplicate
  command walker is deleted. Empty overlay sources no longer emit no-op
  transform scopes — that is what previously made the two paths disagree.
  **The wire format is unchanged**: `BeginRetainedLayer` + complete payload +
  `EndRetainedLayer` still ship every frame, and hit / update / eviction remain
  the renderer session's exclusive decision. P16 constrains the payload and its
  ownership, not how the runtime assembles it, so no RFC was needed.

## Composition-boundary skipping (RFC 0008, new public symbols)

A scoped child feature used to rebuild its entire view whenever the parent
model changed, even when the child view never read the fields that changed —
the counterpart gap to Compose's strong skipping.

ADR 0053 rejected *automatic* builder reuse for lack of an explicit builder-key
contract; ADR 0057 supplied that contract and pre-authorized a convenience
facade once a second adopter appeared. The four hand-written package-global
`Ref` + `physical_equal` memos in `examples/mo_workbench` are that second
adopter, and they are exactly the shape ADR 0057 forbids. RFC 0008 is therefore
a facade over ADR 0057, not the automatic reuse ADR 0053 rejected:

- `Feature::with_view_key` puts the content-key declaration next to the view
  body that reads those inputs, so each mount reuses one reviewable dependency
  set instead of re-deriving it at every call site.
- `Feature::runtime_view_cached` / `ScopedFeature::view_cached` build through a
  **caller-owned** `ViewBuilderCache`, with the builder key distinguishing
  mounts.
- Nothing is inferred and no lifecycle is owned. A feature without
  `with_view_key` builds unconditionally as before — forgetting the declaration
  costs performance, never correctness.

The cache cannot live on the feature value: `Feature::scope` is called with the
same feature value for every sibling, so a shared entry would serve instance
A's view to instance B. `ScopedFeature::view_cached` caches the already-mapped
view; `wrap` is fixed for that `ScopedFeature`'s lifetime, so the map capture
that ADR 0057 requires in the content key is covered by the builder key.

## Views: `text()` content-sized by default (RFC 0007, behavior change)

Leaf text used to carry an implicit `160x32` minimum box, forcing callers to
re-derive pixel sizes at every site, and scaled-up text was clipped inside a
box sized at scale 1.0.

`size` already means *minimum*, so defaulting `width~` / `height~` to `0.0` lets
the existing minimum-box semantics do their job: the measured size wins unless
the caller deliberately asks for a fixed box. `wrap=true` used to collapse an
unset width to a 1px floor; it now takes the incoming layout constraint as the
line width (an explicit `width~` still wins, and the constraint can only narrow
it).

Explicit sizes keep today's exact behavior, and the declaration key already
covers `size`, so there is **no declaration schema change**. RFC 0007's
proposal 2 (buttons and inputs) and the example pixel-size cleanup remain
deferred.

## i18n: CLDR plurals and locale formatting (new public symbols)

Plural selection previously understood only English and Chinese; every other
language silently fell through to `other`.

- `Locale::plural_category` selects by CLDR cardinal category
  (zero / one / two / few / many / other): real mod-10 / mod-100 rules for
  Slavic languages, Arabic thresholds, fr/pt counting zero as `one`, and the
  CLDR 42+ exact-million `many`. `Translator::translate_count` now resolves
  through the category and falls back to `.other` when the catalog lacks the
  selected variant (signature unchanged).
- `Locale::format_int` / `format_number`: locale grouping and decimal
  separators, lakh/crore grouping for en-IN / hi, and `minimumGroupingDigits`
  for pt-PT.
- `Locale::format_date` + `CalendarDate`: numeric date formats driven by an
  explicit field-order table, including the trailing period in ko / hu.
  `CalendarDate::new` returns `None` for an invalid date.

- Each point ran the router's smallest loop first
  (`moon test <pkg-dir> --target native`), and `sh scripts/check.sh --profile pr`
  was green before every commit. CI on the released commit is green across all
  eight jobs, including the full workspace baseline.
- Static validators green: maintenance baseline, api surface, release closures,
  portfolio governance, guidance consistency, renderer capability, doc
  references.
- core's `advanced_core_protocol` classification budget moved 1219 → 1222 with

- Mutation-sensitive tests: the declaration cache, the placement scan, the
  retained-payload replay and the feature view key each have a test that goes
  red when the optimization is disconnected, and each exercises the wired path.
  The retained replay additionally has A/B tests comparing the command stream
  from a memo tree against an isomorphic non-memo tree — that is how the empty

## Upgrading

- From `0.5.2`: update dependencies; no signature breaks. The
  `wzzc-dev/window` dependency is unchanged.
- **One behavior change to watch**: `@views.text(...)` no longer defaults to
  `160x32`. Call sites that relied on that implicit box for alignment or
  spacing should pass `width~` / `height~` explicitly (explicit values behave
  exactly as before). A `wrap=true` call site without `width~` now fills the
  incoming constraint instead of 1px.
- To get composition-boundary skipping: add `with_view_key` to the feature and
  switch the call site to `runtime_view_cached` / `view_cached`, passing your
  own `ViewBuilderCache` and a stable per-mount builder key. See RFC 0008 and
  ADR 0057.
- The declared release line advances to `0.6.x`:
  `checks/portfolio-governance.json`'s `releaseCoupling.line` and the header
  plus 24 base pins in `docs/compatibility-matrix.md` are synchronized; ADR
  0065's Status records this continuation.

# MoUI 0.6.0 — 每帧少做无用功

自 `0.5.2` 以来的功能版本。25 个公开模块统一到 `0.6.0`，发布线声明从
`0.5.x` 推进到 `0.6.x`（延续 ADR 0065 的 synchronized-line 政策，节奏未变，
无需新的 superseding ADR）。

本版六项改动里有四项，去掉的都是「依赖根本没变、框架却每帧照做」的冗余功：
重新编码声明键、layout 一动就整屏重绘、重走子树去推导一份早已扁平的 payload、
以及因为**父** model 变了就重建 scoped 子视图。另外两项是尺寸默认值与
本地化覆盖。六项各自一个 commit，每项都带一个「把优化断线就会红」的变异敏感
测试，且测试走的是被接线的那条路径，而不是自己调 helper。

本版不破坏任何公开签名，只新增公开符号（core 三个组合边界函数、
`moui_i18n` 一组本地化格式 API）。但 `text()` 的默认尺寸是**可见行为变化**
（见下），按兼容性策略进入 minor 而非 patch。

## 运行时热路径（三项，无 API 变化）

- **声明键重复编码**：每个被复用的节点在每次 reconcile 都要把「上一侧」的
  canonical `DeclarationKey` 重新编码一遍，尽管 `declaration()` 对已存字段
  是纯函数、上一侧在两次 reconcile 之间根本不变。现在由 `ElementNode` 携带
  `declaration_cache`，只在赋值 `view_node` 的两个位点（mount 与 reconcile）
  写入，稳态路径上的声明构造减半。
- **`layout changed` → 全屏 damage**：layout 会移动那些从不进入 paint-dirty
  id 集合的干净子树，于是此前只要 layout 跑过就强制整屏重绘，以免它们腾出的
  条带留鬼影。`DamageIndex::placement_changes` 改为按 element id 比较前后两棵
  render tree 的屏幕空间 `paint_bounds` 与 overlay 淡入淡出透明度，只把移动
  id 的「旧 bounds ∪ 新 bounds」并入 damage。`full_damage_reason` 同时拆成
  绝对类（结构、环境、视口、激活、退出鬼影——这些的绘制效果不由位置体现）
  与可被移动扫描收窄的位置类。
- **保留层重复遍历**：P16 要求完整 payload 每帧上线，所以那次拷贝不是可选
  的；可选的是「重新走一遍子树把它推导出来」——payload 在绘制时就已经扁平化
  过，帧构建器却忽略它、每帧为每个后代复合一次变换。现在扁平化直接复用帧
  遍历本身，因此回放的字节就是遍历产出的字节，第二个近乎重复的命令遍历器
  随之删除。空 overlay 源不再发出空操作的变换作用域——那正是此前两条路径
  结果不一致的原因。**线上格式不变**：`BeginRetainedLayer` + 完整 payload +
  `EndRetainedLayer` 仍每帧发送，hit / update / eviction 仍由 renderer session
  独占决定。P16 约束的是 payload 与其归属，不是运行时如何组装它，故无需 RFC。

## 组合边界跳过（RFC 0008，新增公开符号）

scoped 子 feature 此前只要父 model 变化就重建整个子视图，哪怕子视图根本没读
那些变化的字段——这是 Compose strong skipping 的对位缺口。

ADR 0053 曾否决「自动 builder 复用」，理由是缺少显式 builder-key 契约；
ADR 0057 已经提供了该契约，并预授权「出现第二个采纳者后可加便利门面」。
`examples/mo_workbench` 里四处手写的 package-global `Ref` + `physical_equal`
memo 正是那个第二采纳者，也正是 ADR 0057 禁止的形状。RFC 0008 因此是
ADR 0057 之上的门面，不是 ADR 0053 否决的那种自动复用：

- `Feature::with_view_key` 把 content key 声明放在读这些输入的 view 体旁边，
  每个 mount 复用同一份可审查的依赖集合，而不是在每个调用点重新推导。
- `Feature::runtime_view_cached` / `ScopedFeature::view_cached` 通过**调用方
  持有**的 `ViewBuilderCache` 构建，builder key 按 mount 区分。
- 不推断任何键，不拥有任何生命周期。未声明 `with_view_key` 的 feature 照常
  无条件构建——忘记声明只损失性能，不损失正确性。

缓存不能挂在 feature 值上：`Feature::scope` 对每个兄弟都用同一个 feature 值
调用，共享条目会把实例 A 的视图发给实例 B。`ScopedFeature::view_cached` 缓存
的是已经 map 过的视图；`wrap` 在该 `ScopedFeature` 生命周期内固定，因此
ADR 0057 要求计入 content key 的 map 捕获由 builder key 覆盖。

## 视图：`text()` 默认内容尺寸（RFC 0007，行为变化）

叶子文本此前带着一个隐式的 `160x32` 最小盒，调用方只能在每个位点重新推导
像素尺寸，而放大后的文本会在按 scale 1.0 定尺寸的盒子里被裁掉。

`size` 语义本来就是**最小值**，所以把 `width~` / `height~` 的默认值改为 `0.0`
就让既有的最小盒语义自己起作用：测量尺寸胜出，除非调用方刻意要一个固定盒。
`wrap=true` 此前会把未设置的 width 塌成 1px 下限，现在改为取传入的布局约束
作为行宽（显式 `width~` 优先，约束只能收窄它）。

显式尺寸保持今天的确切行为；declaration key 本来就覆盖 `size`，因此
**无 declaration schema 变化**。RFC 0007 的提案 2（button / input）与示例
像素尺寸清理仍然 deferred。

## i18n：CLDR 复数与本地化格式（新增公开符号）

复数选择此前只认识英语和汉语，其他所有语言都静默落到 `other`。

- `Locale::plural_category` 按 CLDR cardinal 类别选择
  （zero / one / two / few / many / other）：斯拉夫语族真正的 mod-10 / mod-100
  规则、阿拉伯语阈值、fr/pt 把 zero 计入 `one`、以及 CLDR 42+ 的
  exact-million `many`。`Translator::translate_count` 改为按类别解析，目录
  缺少所选变体时回退 `.other`（签名不变）。
- `Locale::format_int` / `format_number`：本地化分组与小数分隔符，
  en-IN / hi 的 lakh/crore 分组，pt-PT 的 `minimumGroupingDigits`。
- `Locale::format_date` + `CalendarDate`：由显式字段顺序表驱动的数字日期
  格式，含 ko / hu 的结尾句点。`CalendarDate::new` 对非法日期返回 `None`。

## 升级说明

- 从 `0.5.2` 升级：更新依赖即可，无签名破坏。`wzzc-dev/window` 依赖不变。
- **需要留意的一处行为变化**：`@views.text(...)` 不再默认 `160x32`。依赖
  那个隐式盒做对齐或占位的调用点，请显式传 `width~` / `height~`（显式值语义
  与旧版完全一致）。`wrap=true` 且未传 `width~` 的调用点现在会占满传入约束
  而不是 1px。
- 想吃到组合边界跳过：给 feature 加 `with_view_key`，并在调用点改用
  `runtime_view_cached` / `view_cached` 传入自己持有的 `ViewBuilderCache`
  与稳定的 per-mount builder key。详见 RFC 0008 与 ADR 0057。
- 发布线声明推进到 `0.6.x`：`checks/portfolio-governance.json` 的
  `releaseCoupling.line`、`docs/compatibility-matrix.md` 的线头与 24 条 base
  pin 已同步；ADR 0065 的 Status 记录了本次延续。
