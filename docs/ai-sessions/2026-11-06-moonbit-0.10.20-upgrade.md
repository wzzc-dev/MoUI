# 2026-11-06: MoonBit 0.10.20 toolchain and syntax upgrade

- **Goal**: Upgrade MoUI to the latest MoonBit toolchain, remove upgrade
  warnings, adopt fitting syntax, and prepare the 0.3.2 release.
- **Outcome**: Workspace and Studio migrated to `moonc 0.10.20+65efd5b93`;
  clean `moon check --target all` reports 0 warnings / 0 errors.

## Changes

| Area | Change |
|---|---|
| Toolchain pin | `.moonbit-toolchain` and `moui_studio/.moonbit-toolchain` now pin `0.10.20+65efd5b93`, worker `0.1.202611052`, with integrity hashes |
| Derive syntax | `1,244` first-party migration sites became `#derive(...)` attributes (`1,216` workspace code, `27` Studio code, `1` embedded export-kernel template) |
| Derive tooling | `generate_core_derives` stages `#derive` before binding it to the following type and rejects deprecated suffix syntax |
| JSON migration | `to_json().stringify()` became `Json(value).stringify()`; generated interfaces now name `@json.Json` |
| Warning cleanup | Boolean `inspect` assertions use `assert_true`/`debug_inspect`; `not(expr)` uses `!expr`; test roots carry explicit `View[Unit]` types |
| Standard-library API | `String::offset_of_nth_char` callers use the renamed `start=`/`end=` labels |
| Versions | All 25 public modules and workspace pins are `0.3.2`; `moui_cli` defaults follow; Studio is `0.1.5` |
| Exported projects | The embedded `ControlProps` kernel source now emits `#derive(Eq)`; an export test rejects any old suffix syntax in generated `.mbt` files |
| Docs | Toolchain migration notes, 0.3.x release order, and release notes `0.3.2` updated |

## Syntax Decisions

- Adopted `#derive`, `!expr`, `Json(...)`, `Debug`/`debug_inspect`, and the new
  generated-interface layout.
- Migrated the one derive declaration embedded as export-kernel source text;
  `moon fmt` cannot rewrite attributes inside string templates.
- Did not add `reb"..."` byte regex, top-level `declare let`, or
  `Float::total_compare`: no existing MoUI path benefits without adding a new
  untested consumer or changing stable generated wire snippets.
- Kept `Int` in generated ABI strings where it is an alias; new FFI/wire code
  should use explicit `Int32`/`UInt32`.
